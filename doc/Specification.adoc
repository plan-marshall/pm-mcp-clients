== Overview

This document is the index of the technical specifications of the clients of *plan-marshall-mcp* (`PM-MCP`): the
specification parts the modules of this repository (`pm-api`, `pm-exec`, `pm-relay`, `pm-operator`,
`pm-mock-runtime`, `pm-web-app` and `pm-web-e2e`) implement, kept beside the code so that a work package changes
code, tests and specification in one pull request. The requirements
(link:../../plan-marshall-documentation/doc/Requirements.adoc[Requirements Document]), the use cases, the roadmap,
`later-improvements`, the open questions and the articles stay in `plan-marshall-documentation`, together with the
specifications of `pm-mcp-parent` (the
link:../../plan-marshall-documentation/doc/specification/module-structure.adoc[Module Structure Specification] among
them) and the archetypes that span every specification
(link:../../plan-marshall-documentation/doc/implementation-watch/cross-cutting.adoc[`cross-cutting.adoc`]). The
specifications the daemon implements stay in `plan-marshall-documentation` until they move into `plan-marshall-mcp`. The watch items of the specifications here are
collected in the link:ImplementationWatch.adoc[Implementation Watch of `pm-mcp-clients`]; what each implemented
requirement is implemented by, verified by and documented in is recorded in link:Traceability.adoc[Traceability]. How
the specification relates to the design of the two clients is ADR
link:adr/001-specifications-of-the-clients.adoc[001 The Specifications of the Clients in This Repository].

The lifecycle states of a specification (`PLANNED`, `IN PROGRESS`, `REFERENCE`, `DEPRECATED`), the condensation and
pointing of implemented sections and the traceability rules are those of the
link:../../plan-marshall-documentation/doc/Specification.adoc[Specification index] of the documentation; they apply
here unchanged, with the links to the requirements written as relative sibling paths into
`plan-marshall-documentation`. The developer documentation of a module of this repository lives beside its code in
`<module>/doc/developer/`, as in `pm-mcp-core`; a condensed section points there, and the `Documentation:` lines of
link:Traceability.adoc[Traceability] link it, never a specification part.

== Specification Index

The links between the documents of this tree are relative; a link into another repository is a relative sibling path
that resolves with the repositories checked out beside each other, and those repositories link into this tree with
absolute `https://github.com/plan-marshall/pm-mcp-clients/blob/main/doc/...` URLs. `trace.py` of the
documentation checks the links of this tree outwards and the links into it, anchors included, run against a checkout
of this repository beside it. It is run locally before every merge.

Four families are split across two repositories at a heading, and each holds a family index here that lists the parts
of this repository alone: `cli-and-security`, `runtime-model`, `harness-integration` and `job-runtime`. A section lives
in the repository whose code implements it; a section both repositories implement, with no heading between the two
halves, stays where it is and is named as shared (ADR link:adr/001-specifications-of-the-clients.adoc[001]). For
`cli-and-security` and `runtime-model`, a family's `Overview`, `Traceability`, `Status` and the daemon's `Modules` rows
stay with the family index of `plan-marshall-documentation` until the daemon's parts move into `plan-marshall-mcp`; for
`job-runtime` they stay with the family index of `pm-mcp-core`; `harness-integration` keeps only its `Bundle Content
per Harness` section with the model-facing content there, so its index here carries the family's `Overview`,
`Traceability` and `Status`.
