[#event-catalogue]
== Event Catalogue
_See Requirement link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-ARCH-11[PM-ARCH-11: The Operator's Two Clients & Their Contract]_

The closed catalogue of the events the runtime streams to the operator's clients (link:../../../../plan-marshall-documentation/doc/specification/runtime-model/01-processes-and-transport.adoc#event-streams[Events per Scope]). Every event has a name of the event name grammar (link:https://github.com/plan-marshall/pm-mcp-core/blob/main/doc/specification/identifiers/02-registry-stores-to-web.adoc#id-event-name[Identifier Registry, Event Name]), one payload schema in `pm-api`, and the streams it is sent on; the envelope (`event`, `at`, `scope`, the SSE `id`) is that of link:../../../../plan-marshall-documentation/doc/specification/runtime-model/01-processes-and-transport.adoc#event-streams[Events per Scope] and is not repeated below. A payload carries identifiers, states, counts, and message keys with their arguments; text of a model, a provider, or a harness travels only in the entries of a task's activity stream, marked untrusted, and in the chat's turns (<<chat-events>>), shown by the chat's text rule. A new event, a new payload field, or a new stream for an event is a change of `pm-api`, checked by the mock runtime's load validation and the drift replay (link:05-mock-runtime.adoc[Mock Runtime]).

Streams: *R* the runtime-wide stream, *P* a plan's, *E* an epic's, *W* a project's workspace scope's, *M* the machine scope's, *N* an entry's, *Rep* the reports stream, *A* a task's activity stream.

=== Stream Control

[cols="2,1,3"]
|===
|Event |Streams |Payload

|`reset` |all |none: the events after the client's `Last-Event-ID` are no longer held, or the runtime started since; the client reads the scope's resources again
|`stream.closed` |all |`reason` (`device_revoked`, `device_expired` (the device's idle expiry, link:../../../../plan-marshall-documentation/doc/specification/cli-and-security/03-web-server.adoc#devices[CLI, Coordination & Security Specification, Devices in Both Clients]), `listener_closed`, `runtime_stopping`, `scope_ended`), for `device_revoked` the channel and device that revoked it and when: the stream ends after it; `scope_ended` names the scope's successor stream where there is one (an entry's started scope, a project onboarding's workspace scope)
|===

[#chat-events]
=== Chat
_See Requirement link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-WF-24[PM-WF-24: Chatting with the Planning Role]_

The events of a chat are sent on the stream of the scope that holds it: a plan's chat on *P*, an epic's (its draft and registers included) on *E*, an entry's on *N*, a decision's on the stream of its scope (a plan, an epic, an entry, or a project's workspace; a decision of the machine scope has no chat), and ended work's on *W* (link:../../../../plan-marshall-documentation/doc/specification/runtime-model/01-processes-and-transport.adoc#chat-routes[The Chat's Routes]). Every device that shows the chat sees each turn, proposal, and end as it happens. A client that missed events (a `reset`) reads the chat again; a turn being written is read with its text so far.

[cols="2,1,3"]
|===
|Event |Streams |Payload

|`chat.turn.started` |P, E, W, N |`chat_id`, `turn_id`, `kind` (`message`), the author (`operator` or the role), `format`, `untrusted`, the `model` of a role's turn, and on a role's turn the chat's `context` as refreshed for this turn, a re-primed worker's included (link:../../../../plan-marshall-documentation/doc/specification/runtime-model/01-processes-and-transport.adoc#chat-routes[The Chat's Routes]); the operator's message carries its `text` and is announced by this event alone
|`chat.turn.delta` |P, E, W, N |`chat_id`, `turn_id`, `text`: the next piece of the reply, appended in the order of the stream
|`chat.turn.progress` |P, E, W, N |`chat_id`, `turn_id`, `step`: a step of the role's work the runtime derives from the worker's activity (the target read, the check run) as a message key with its arguments, never the model's own words
|`chat.turn.completed` |P, E, W, N |`chat_id`, `turn_id`, `kind` (`message`, `notice`), `status` (`complete`, `stopped`, `failed`), `untrusted`, the turn's whole `text`, `refs` (each with its `kind`: `task`, `file`, `decision`, `plan`, `hold`, or `act`, an act the role names), and for `failed` its `reason` (`infeasible`, `lost`, `too_long`: the reply exceeded the chat reply bound) as a message key with its arguments; a notice is announced by this event alone, and a notice the runtime writes about the chat's subject carries `lines[]`, the narrative lines it reports, each `key`, `args`, `refs`, and `at`, written between replies and never inside a reply being written
|`chat.proposal` |P, E, W, N |`chat_id`, the proposal's own `turn_id`, `reply_turn_id` of the reply that proposed it, the proposal's `kind`, and its `state` (`open`, `replaced`, `accepted`, `rejected`, `applied`, `refused` with its finding, `lapsed`; link:../../../../plan-marshall-documentation/doc/specification/runtime-model/01-processes-and-transport.adoc#chat-proposal-states[A Proposal's States]); a plan's revision `accepted` is its `queued_revision` until it is `applied`, `refused`, or `lapsed`, each announced by `plan.revision_queued`
|`chat.ended` |P, E, W, N |`chat_id`, `ended_by` (`operator`, `proposal_carried`, `answered_elsewhere`, `subject_ended`, `entry_closed`), the channel and device where the operator ended it
|===

[#client-text-hidden-characters]
== No Hidden Character Reaches a Client
_See Requirement link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-SEC-1[PM-SEC-1: Two-Boundary Security Model & Untrusted Content Containment]_ +
_Implementation watch: link:../../implementation-watch/runtime-model.adoc#PM-WATCH-RUN-18[PM-WATCH-RUN-18]_

The encoder of `pm-api` removes from every string value of a response and of an event's `data` on `/api/v1` every code point of the hidden-character classes (link:https://github.com/plan-marshall/pm-mcp-core/blob/main/doc/specification/job-runtime/03-parsers-and-gates.adoc#hidden-character-classes[Job Runtime Specification, Ingestion Validator, Hidden characters], stage 1), in one pass, without exception and without a report. It holds for every text, whoever wrote it (a model, a repository, a provider, the operator, the message catalogue), so that a bidirectional override, a zero-width character, or a terminal escape cannot make what a client shows differ from what the operator reads or copies; the printable rest of an escape sequence stays visible as text, and an emoji joined by a zero-width joiner is shown as its parts. The filter changes what is served, never what is stored: the records, the plan's files, and the texts a model reads keep their characters, so the added-line scan, the outbound text check, and the audit trail still see them. The mock runtime serves through the same encoder (link:05-mock-runtime.adoc[Mock Runtime]).
