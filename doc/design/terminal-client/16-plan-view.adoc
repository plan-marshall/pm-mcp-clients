What the plan view shows, level by level, is link:../shared/plan-view.adoc[Plan View], for both clients (link:../../../../plan-marshall-documentation/doc/use-cases/03-plans.adoc#UC-PLN-1[UC-PLN-1]). This part is how the console draws it: as the third level of the full-screen view of xref:15-overview.adoc[The Overview], and as a tree in the scrollback. The conventions of the transcripts are those of xref:05-transcripts-entry.adoc#transcripts[Transcripts].

[#plan-view-ways]
== Two Ways

* *In the full-screen view*: `Enter` on a plan in `plans` opens its plan view in the same view; `Esc` goes back to the project (<<full-screen>>).
* *`plan <plan_id>`* prints the plan's process as a tree into the scrollback, opened down to where the plan is; `--all` opens every level, `--depth <n>` opens n levels (<<tree>>). It is the accessible path and the fallback of the full-screen view, as `status` is for the overview.

[#full-screen]
== In the Full-Screen View

[#full-screen-tree]
=== A Tree to Open and Close

----
 fix-relay › execute                                                   ● connected
 fix-relay · execute · running · 2 h 10 min · #214                relay-hardening
 ─────────────────────────────────────────────────────────────────────────────
   ✓ phase  init                                    done · 2 min
   ✓ phase  refine                                  done · 14 min
   ✓ phase  outline                                 done · 31 min
   ✓ phase  plan                                    done · 9 min
 ▾ ▶ phase  execute                                 running · 25 min
     ✓ envelope-ready                               done ×2
▶  ▾ ▶ envelope-ready                               running · run 3
         ▶ tasks  4 of 7 tasks done
     ○ envelope-close                               planned
 ▸ ○ phase  finalize                                planned
 ─────────────────────────────────────────────────────────────────────────────
 ↑↓ move   → open   ← close   Enter details   . where it is   a actions   Esc back
----

* The plan view is a tree: `▸` a closed node, `▾` an open one; `→` (`l`) opens the selected node one level, `←` (`h`) closes it or moves to its parent.
* It opens with the path to the plan's current position open and the selection on the running leaf; `.` jumps there again from anywhere.
* The header is the path from the plan to the selected node, and below it the plan's line: its phase, its state, since when it runs, its own pull request by its number (a terminal hyperlink, OSC 8, where the terminal shows one), and its epic.
* *The state* is one of the closed list of link:../shared/plan-overview.adoc#texts[Plan Overview, Texts]: `running`, `pausing after the task` or `pausing after the phase`, `paused`, `waiting for you`, `held`. A held plan names its hold after it, with its kind and since when (`execute · held · holds: a condition since 14:02`), and `a` offers its acts (xref:19-actions.adoc#holds[What Holds a Plan]).
* `a` opens the plan's actions below the header (xref:19-actions.adoc#full-screen[Actions]).
* `Enter` on a leaf shows its details below it (<<full-screen-leaf>>); on a node that waits for the operator it leaves the view and opens the decision, as `answer` does.

[#full-screen-sub]
=== Sub-Workflows

----
 fix-relay › finalize › remediation.ci-failure                         ● connected
 ─────────────────────────────────────────────────────────────────────────────
 ▾ ▶ phase  finalize                                running · 40 min
     ✓ create-pr                                    done
     ✓ automatic-review                             done
   ▾ ▶ ↳ sub-workflow  remediation.ci-failure       running · run 2
       ✓ analyze                                    done ×2
     ▾ ▶ ↳ sub-workflow  git.commit_and_push        running
▶        ▶ push                                     running · 0:12
         ○ verify-remote                            planned
       ○ await-ci                                   planned
     – await-waiver                                 not taken
     ○ merge                                        planned
 ─────────────────────────────────────────────────────────────────────────────
----

* A sub-workflow's line carries `↳` and the word `sub-workflow`; it opens like a phase, through every level of nesting.
* A branch not taken is `–` with `not taken`; it is shown where the workflow branched and opens to show what it would have run.

[#full-screen-keys]
=== Keys

The keys of the overview hold here too (xref:15-overview.adoc#full-screen-keys[Keys]); those of this table replace them where both name a key: `→` (`l`) and `←` (`h`) open and close nodes instead of moving between levels, and `Enter` shows a leaf's details instead of opening a row. `Esc` goes back to the overview.

[cols="1,3",options="header"]
|===
|Key |Action

|`→`, `l`
|open the selected node one level (replaces _open_ of the overview)

|`←`, `h`
|close the selected node, or move to its parent (replaces _back_ of the overview)

|`Enter`
|on a leaf, its details; on a node that waits for the operator, the decision (replaces _open_ of the overview)

|`a`
|the plan's actions, below the header; on a node that holds, the acts of the hold

|`.`
|jump to where the plan is

|`*`
|open every level below the selected node

|`n`
|show or hide the nodes not in this plan
|===

[#full-screen-live]
=== Live

The tree follows the plan's events; the selection stays on its node. When the plan changes its composition, the view reads the process again and prints `The plan changed: replan` in the header for a moment; when the plan ends, the header says so and the tree stays as it ended.

[#ended]
=== An Ended Plan

A plan that has ended, opened from ended work (xref:15-overview.adoc#ended[Ended Work]) or by `plan <plan_id>`, shows as it ended, read from the archive: the header names its outcome, its reason, and when it ended (`fix-relay · cancelled 2 d ago · the approach is replaced by plan relay-v2`; the outcomes of link:../shared/work-actions.adoc#outcomes[How a Plan Ends]); the tree is the process as it was when the plan ended, opened down to where it stopped; nothing updates, and `a` offers _Chat…_ alone (`fix-relay has ended: its view, and a chat about it`; xref:19-actions.adoc#chat-ended[A Chat About Ended Work]).

[#tree]
== The Tree (`plan`)

[source,text]
----
pm › plan fix-relay
fix-relay · execute · running · 2 h 10 min · pull request #214 https://github.com/plan-marshall/pm-mcp-clients/pull/214
  done      phase init                       2 min
  done      phase refine                     14 min
  done      phase outline                    31 min
  done      phase plan                       9 min
  running   phase execute                    25 min
    done ×2   envelope-ready
    running   envelope-ready                 run 3 · tasks: 4 of 7 done
    planned   envelope-close
  planned   phase finalize
pm ›

pm › plan docs-typo
docs-typo · execute · running · 3 min
  done      phase init                       1 min
  running   phase execute                    2 min
    running   sub-workflow land
  planned   phase finalize
  not in this plan: refine, outline, plan (the land lane)
pm ›
----

* The tree uses words for the states, so that it reads the same without glyphs and colour; sub-workflows carry the word `sub-workflow`. A plan of the land lane shows its `land.*` states as the sub-workflow `land` within `execute`, and the phases the lane does not call as not in this plan; `land` is never a phase.
* `plan fix-relay --all` opens every level; `--depth 2` opens two.
* The first line carries the state from the same closed list as the full-screen header, the hold with its kind where one holds, and the plan's pull request by its number and its URL. An ended plan prints `ended` with its outcome instead (`fix-relay · ended: cancelled · 2 d ago`) and the tree as it ended.
