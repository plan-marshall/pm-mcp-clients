What the explorer and a project's onboarding show is link:../shared/project-explorer.adoc[Project Explorer] and link:../shared/project-onboarding.adoc[Project Onboarding], for both clients (link:../../../../plan-marshall-documentation/doc/use-cases/04-projects.adoc[Use Cases, Projects]). This part is how the console draws them. The conventions of the transcripts are those of xref:05-transcripts-entry.adoc#transcripts[Transcripts].

[#commands]
== Commands

----
  projects [--list]                     the explorer, full screen; --list prints it into the scrollback
  project add [<path>]                  onboard a project; the working directory is the proposed checkout
  project setup <project_id> [<step>]   a later run of a project's onboarding, at a step (team, own, roles, commit)
  project favourite <project_id> [--off]
----

* All are operator verbs and run in the console or as one shell command (xref:01-commands.adoc#command-tree[The Verbs]); `pm-operator enrol` stays the direct verb of a project's enrolment, with its arguments as the answers of `project.identity` to `project.enrol`.
* `--project ?` of every other verb shows the same list as the explorer, favourites first (xref:02-levels.adoc#addressing[Addressing a Level]).

[#explorer]
== The Explorer, Full Screen

`projects` opens the explorer as the first level of the full-screen view of xref:15-overview.adoc[The Overview]: from a project, its actions; from _Running work_, the project's level of the overview; from a plan, its plan view (xref:16-plan-view.adoc[The Plan View]).

----

▶ ★ pm-mcp-clients    ready      ! 2   3 plans · 1 orchestrator    2 min ago
  ★ pm-mcp-core       ready            2 plans                     9 min ago

    plan-marshall     setup needs: credential sonar                yesterday
    cui-http          ready                                        3 d ago
 All projects · by name
    API-Sheriff       ready                                        5 weeks ago
    …
 ─────────────────────────────────────────────────────────────────────────────
 ↑↓ move   Enter actions   * favourite   s sort   / filter   + add   q leave
----

`Enter` on a project opens its actions in place:

----
▶ ★ pm-mcp-clients    ready      ! 2   3 plans · 1 orchestrator    2 min ago
      o  Add an orchestrator
      p  Add a plan
      r  Running work
      e  Setup
      *  Remove from favourites

A released project offers instead `a  Enrol again`, which runs its onboarding again from `project.identity` with its current values (as `pm-operator enrol` does), and `r  Running work` while plans of it still show.
----

[cols="1,3",options="header"]
|===
|Key |Action

|`Enter`
|the actions of the selected project; on an action, that action

|`o`, `p`, `r`, `e`
|add an orchestrator, add a plan, running work, setup: directly from the row

|`a`
|on a released project: enrol it again

|`*`
|mark or unmark the selected project as a favourite

|`J`, `K`
|move a favourite down or up in the favourites

|`s`
|sort _All projects_ by name or by most used

|`/`
|filter by name and id; the groups become one list of matches

|`+`
|add a project: leaves the view and starts `project add`
|===

The keys of the explorer are keys of navigation, the same in every language, like those of the overview (xref:15-overview.adoc#full-screen-keys[Keys]). The two _Add_ actions leave the view and start `orchestrator add` and `plan add` for the project (xref:18-starting.adoc[Starting Work]); while an entry of the project is open, `Enter` offers `s  Continue starting` first.

* `project add <path>` starts with that path; in a checkout, the working directory is the proposal.
* A later run (`project setup pm-mcp-clients own`) opens the same states with the project's current values; a project that is not ready continues where its setup stopped.
