* `language.detect` and `language.record` print no line of their own beyond the result; `language.done` is the result line.
* The state opens in the system's language where a pack exists (`LC_ALL`, `LC_MESSAGES`, `LANG`), else in English. A change of the interface language reprints the whole state in it before it is recorded, so the operator reads it first; a change of the model language marks the line `✎` and changes nothing else (xref:03-dialogues.adoc#language[Language of the Terminal]).

[#t-harness]
== 2 Harnesses

One scan finds every harness the profiles know; the operator chooses the ones to enrol and one of them as the default, on which the steward of the later steps runs with that harness's default model, outside the model catalogue (link:../../../../plan-marshall-documentation/doc/use-cases/01-onboarding.adoc#UC-ONB-4[UC-ONB-4]). Every consent state is the shared pattern (link:../shared/consents.adoc#pattern[Consents, The Pattern]; xref:03-dialogues.adoc#consent[Consent]).

[#t-harness-consent]
=== Consent and Scan (`harness.consent`, `harness.scan`)

[source,text]
----
[2/7] Harnesses · Look for harnesses on this machine?
  looks for   claude, opencode, codex, agy
  in          your PATH, ~/.local/bin, /Applications, /opt/homebrew/bin
  runs        <program> --version on each one found
  never       reads other files, starts a session, uses the network
  tokens      none

y) yes   r) yes, and don't ask again   n) not now   ?   › n
  Nothing was done.
y) yes   r) yes, and don't ask again   n) not now   ?   › y
  ⠼  Looking for harnesses …  2 of 4 programs
  ✓  Looking for harnesses: 3 found
----

* The scan is one: every executable of every profile, in the directories of the login `PATH` and the profiles' install locations, with its version probe and nothing else (link:../../../../plan-marshall-documentation/doc/use-cases/01-onboarding.adoc#change-harness-scan[Harness Scan]).

[#t-harness-none]
=== None Found (`harness.none`)

[source,text]
----
[2/7] Harnesses · No harness found
  Looked for claude, opencode, codex, agy in your PATH, ~/.local/bin,
  /Applications, /opt/homebrew/bin.

  Install one, then look again:
    Claude Code   https://docs.anthropic.com/en/docs/claude-code/setup
    OpenCode      https://opencode.ai/docs/
  Or add a harness that is not listed, by its program.

Add a harness that is not listed? [Enter]   l) look again   q) later   ?   ›
----

* `harness.none` is the operator's choice: `Enter` adds a harness (`harness.add`), `l` scans again (`harness.scan`), and `q` is _later_: nothing is sent, the onboarding rests in `harness.none`, and its next run, here or in the web app, resumes there (xref:03-dialogues.adoc#keys[Links as Keys and Numbers]).
* The step cannot finish without one usable harness. When every chosen harness fails its check, `harness.probe` leads here as well, with the failed checks in place of what was looked for:

[source,text]
----
[2/7] Harnesses · No harness can be used
  None of the chosen harnesses passed its check:
    Claude Code   ✗ not logged in            → claude login
    OpenCode      ✗ version 1.2.0 is not supported (1.5 – 1.x)
                                             → install a version in 1.5 – 1.x

  Fix one, then look again, or add a harness that is not listed.

Look again? [Enter]   a) add a harness that is not listed   q) later   ?   ›
----

[#t-harness-icons]
=== Icons (`harness.icons-consent`, `harness.fetch-icons`)

The terminal shows no icon. It asks the consent all the same, because the runtime fetches the icons once for both clients and the web app shows them; a run in the terminal and a later look in the web app are one machine (link:../../../../plan-marshall-documentation/doc/use-cases/01-onboarding.adoc#change-harness-icons[Harness Icons], link:../web-app/harness-icons.adoc[Web App, Harness Icons]).

[source,text]
----
[2/7] Harnesses · Fetch the makers' icons of the found harnesses?
  looks for   the makers' icons of Claude Code, OpenCode, Codex
  runs        one download of each, by the runtime, from the address in its
              profile; stored on this machine
  never       sends data of yours or of this machine; the maker's server sees
              only a download request from this machine's address (through
              the proxy, if one is set); your browser never loads them
  tokens      none
  Only the web app shows them. With n it shows monograms.

y) yes   r) yes, and don't ask again   n) not now   ?   › n
  Nothing was fetched; the web app shows monograms.
----

* `n` goes on, unlike the other consents of the step: an icon is no condition (link:../shared/consents.adoc#kinds[Consents, The Kinds], `fetch_icons`). The next state follows at once.
* With `y` or `r`, `harness.fetch-icons` prints one line, `✓ Icons fetched: 3`; a failed fetch adds a line of its own, `The icon of Codex was not fetched: the address answered 404. Its monogram stays.`. A remembered consent prints its line and the fetch line (xref:03-dialogues.adoc#consent[Consent]).

[#t-harness-choose]
=== Choose (`harness.choose`)

[source,text]
----
[2/7] Harnesses · Choose the harnesses to enrol
  Found on this machine:
    1) [x] Claude Code   2.4.1   ~/.local/bin/claude         ✓ supported   ★ default
                                 tokens complete
    2) [x] OpenCode      1.9.0   /opt/homebrew/bin/opencode  ✓ supported
                                 tokens complete
           Codex         0.31.2  /opt/homebrew/bin/codex     ✗ cannot run workers
                                 tokens not reported
           Antigravity   —       not found

  The default runs the steward of the next steps and is proposed for new
  roles.

Check 2 harnesses, Claude Code the default? [Enter]   toggle: 1-2   d) set the default   a) add a harness that is not listed   l) look again   ?   › d
  default   1) Claude Code ←   2) OpenCode   › 2
    2) [x] OpenCode      1.9.0   /opt/homebrew/bin/opencode  ✓ supported   ★ default ✎
Check 2 harnesses, OpenCode the default? [Enter]   toggle: 1-2   d) set the default   a) add …   l) look again   ?   › d
  default   1) Claude Code   2) OpenCode ←   › 1
Check 2 harnesses, Claude Code the default? [Enter]   toggle: 1-2   d) set the default   a) add …   l) look again   ?   › ⏎
----

* Every supported harness found is preselected, the first of them the default (link:../../../../plan-marshall-documentation/doc/use-cases/01-onboarding.adoc#preselect-first[Preselect as much as possible]). A harness that cannot run workers is listed without a number and with its reason; one not found is listed so that the operator sees what was looked for.
* The default is one of the chosen ones: unchecking it moves the mark to the first chosen one that is left, and a line says so (`OpenCode is now the default.`). With none chosen the prompt reads `Choose at least one: 1-2   a) add …` and has no `Enter`.
* `a` is what the web app keeps under _Advanced_ (<<t-harness-add>>); the terminal offers it in the prompt line.
* *What a harness reports of its tokens* stands below each found harness, from its profile and, for a verified profile, from its verification (link:../web-app/onboarding.adoc#harness-tokens[Web App, Onboarding, What a Harness Reports]): `complete`, `partial` with what is missing (`partial: no cache figures`), or `not reported`. It is information, never a condition: a harness that reports less is chosen and enrolled like any other, and its tasks' figures say what was not measured.

[#t-harness-probe]
=== Check (`harness.probe-consent`, `harness.probe`, `harness.blocked`)

[source,text]
----
[2/7] Harnesses · Check whether the chosen harnesses are logged in?
  runs        claude auth status   (Claude Code)
              opencode auth list   (OpenCode)
  never       starts a session, sends a prompt
  tokens      none

y) yes   r) yes, and don't ask again   n) not now   ?   › r
[2/7] Harnesses · Checking 2 harnesses
  Claude Code
    ✓  version 2.4.1 is supported (2.0 – 2.x)
    ✗  not logged in
       → log in to Claude Code in another terminal, then check again:
         claude login
  OpenCode
    ✓  version 1.9.0 is supported (1.5 – 1.x)
    ✓  logged in

Check Claude Code again? [Enter]   x) leave it out   o) choose again   ?   › ⏎
  Claude Code
    ✓  version 2.4.1 is supported (2.0 – 2.x)
    ✓  logged in
----

* One consent covers the login probes of every chosen harness, each named in `runs`. A harness whose profile has no login probe is checked by one minimal headless call; the consent states the call and the tokens it uses (link:../../../../plan-marshall-documentation/doc/use-cases/01-onboarding.adoc#change-login-probe[Login Probe]):

[source,text]
----
  runs        claude auth status   (Claude Code)
              one minimal headless call of Aider
  never       reads your repositories
  tokens      about 2.0 k tokens of your Aider account
----

* `harness.blocked` is asked for each failing harness in turn, under its name, while at least one chosen harness passes; when none does, the state is `harness.none` (<<t-harness-none>>). `x` leaves it out: the step goes on to `harness.confirm` without it, and if it was the default, the mark moves to the first one left (`★ default ✎` there). The last harness left cannot be left out: its prompt has no `x`. `o` returns to `harness.choose` with the current choice. A harness left out stays found and is offered again by a later run; `harness.confirm` names it `left out`.

* `harness.add-consent` has no `r`: running an unknown program is asked for every time (`verify_harness_profile`, link:../shared/consents.adoc#kinds[Consents, The Kinds]).
* After the installation the run returns to `harness.choose` with the added harness among the found ones and chosen; its check and enrolment are those of every chosen harness. A profile that cannot run workers is installed, listed without a number, and cannot be the default.
* The stage `usage` reads the usage of the real output of the stages before it and records for each figure (input, output, cache read, cache write, reasoning) whether this harness and version reports it, declares it not applicable, or does not report it; it fails only where a figure the draft names cannot be read. Its result is the `Tokens` line of the profile.
* A field of the draft is asked as a line with its current value in brackets; `Enter` keeps it. A known harness found nowhere is added by its path only: its shipped settings are used and not asked.

[#t-models]
== 3 Models (`catalogue.consent`, `catalogue.models`, `catalogue.advise`, `catalogue.select`, `catalogue.record`, `catalogue.done`)

The harnesses are enrolled in step 2; this step only asks them for their models and records the allowed ones (link:../../../../plan-marshall-documentation/doc/use-cases/01-onboarding.adoc#UC-ONB-5[UC-ONB-5]).

[source,text]
----
[3/7] Models · Ask the harnesses for their models, and a model for advice?
  1  List the models of Claude Code and OpenCode
       runs   claude models list, opencode models
       tokens none
  2  Ask the steward which models suit which work
       runs   a steward task on the default harness, Claude Code · opus-5.5
       tokens not known yet: first run

  1  List the models?   y) yes   r) yes, and don't ask again   n) not now   ?   › y
  2  Ask the steward?    y) yes   r) yes, and don't ask again   n) no, without advice   ?   › y
  ✓  Claude Code    3 models
  ✓  OpenCode       5 models
  ⠴  steward is working on Claude Code · opus-5.5      0:18   about 50 k tokens

[3/7] Models · Choose the models plans may use
  Recommendation by steward: Claude Code for writing roles, OpenCode with a
  small model for screening; allow the four models below.   ?0 why

  Claude Code   ★ default
    1) [x] opus-5.5         ★ recommended
    2) [x] sonnet-5.5       ★ recommended
    3) [ ] haiku-5.5
  OpenCode
    4) [x] qwen-coder-32b   ★ recommended
    5) [x] deepseek-v4      ★ recommended
  a) add a model id

Allow 4 models? [Enter]   toggle: 1-5   b) back   ?   › 3
    3) [x] haiku-5.5        ✎
Allow 5 models? [Enter]   toggle: 1-5   b) back   ?   › ⏎
✓ 5 models allowed on 2 harnesses
----

* The two consents of `catalogue.consent` are the kinds `probe_harness_models` and `model_advice` (link:../shared/consents.adoc#kinds[Consents, The Kinds]), answered one after the other, each with `y`, `r` (remembered for its own kind), and `n`. `n` to the model probes leaves the step where it is (`Nothing was done.`) and the second is not asked; `n` to the advice goes on to `catalogue.select` without a recommendation. A remembered consent is shown as its line and not asked; with both remembered the state is passed.
* The steward runs on the default harness chosen in step 2, with that harness's default model (link:../../../../plan-marshall-documentation/doc/use-cases/01-onboarding.adoc#change-steward-role[Steward Role]); a failed or left task leads to `catalogue.select` without a recommendation and the line `– The steward gave no proposal: <reason>.`
* `?0` is the recommendation's rationale, `?n` the rationale of item `n` with its limits.
* A harness that cannot list its models shows `a) add a model id` as its only entry; `a` asks `Model id for OpenCode › `. A harness of which no model is allowed stays enrolled and is used by no role; the result line names it (`OpenCode: no model allowed`).
