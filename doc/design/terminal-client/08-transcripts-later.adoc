== Later Changes and Scripts

The first two run a verb as one shell command, as a script does, and so does `config providers --verify`; the others run it in the console.

* Only the changed role is written to the project's assignment; the others keep following the machine, so a later machine change reaches them. `d` removes the project's value of the selected roles.

[#t-consents]
=== The Remembered Consents (`config consents`)

[source,text]
----
pm › config consents
Consents · The consents you said not to ask again
    1) look for harnesses                 scan_harnesses        12 May, 10:14
    2) check whether a harness is logged in   probe_harness_login   12 May, 10:15
    3) look for CLI tools and stored tokens   scan_providers        12 May, 10:21
    4) approve the cost of a role task    model_cost · pm-mcp-clients   3 Jun, 16:02

  A withdrawn consent is asked again the next time its action runs.

Withdraw: 1-4   q) leave   ?   › 2 4
    2) check whether a harness is logged in   ✎ withdraw
    4) approve the cost of a role task        ✎ withdraw
Withdraw 2 consents? [Enter]   toggle: 1-4   q) leave   ?   › ⏎
✓ 2 consents withdrawn; they are asked again the next time.
----

* The list is what the runtime remembers: the action, its consent kind, the project for a consent of a project (`model_cost`), and when it was given. A consent is never given here; it is given only where its action asks (xref:03-dialogues.adoc#consent[Consent]).
* With no remembered consent the verb prints `No consent is remembered.` and returns.

[#t-providers-verify]
=== Providers Checked Again (`config providers --verify`)

[source,text]
----
$ pm-operator config providers --verify
Providers · Checking the providers again
  GitHub (gh)                                                ✓ ready
    last check  ✓ ready, 12 May, 10:24
    ✓  github.com reachable
    ✓  token authenticates as oliver-wolff (fine-grained, expires in 9 days)
    ✓  permissions: contents, pull requests, checks (read and write)
    ✓  gh 2.71 is logged in as the same account
  SonarCloud                                                 ✗ not ready
    last check  ✓ ready, 12 May, 10:24
    ✓  sonarcloud.io reachable
    ✗  token refused: 401 "Invalid token"
       → enter the token again

Enter the token again? [Enter]   l) check again   k) continue without SonarCloud   ?   › ⏎
Providers · SonarCloud needs a token
  …
Token (not shown while you type): ›
Store and check it? [Enter]   b) back   ?   › ⏎
  SonarCloud                                                 ✓ ready
    ✓  sonarcloud.io reachable
    ✓  token authenticates as oliver-wolff (user token, no expiry known)
✓ Providers checked: GitHub ready, SonarCloud ready. GitHub: the token expires in 9 days.
----

* `--verify` runs `providers.verify` on the recorded providers; each shows the result and the time of its last check before the new one. With every check `✓` nothing is recorded and the verb ends; a failed check leads to `providers.failed`, as in the onboarding (xref:07-transcripts-steps-4-7.adoc#t-providers-verify[Check]). With `--project <project_id>` it checks the project's providers.
* A token that expires within 14 days is named in the result line.

[#t-devices]
=== Paired Devices (`web devices`)

[source,text]
----
pm › web devices
Paired devices · The browsers that can act on this machine
    1) Firefox on mbp-oliver     paired 12 May   last used today 14:02   loopback   this one
    2) Safari on iPad            paired 20 May   last used 3 d ago       network
    3) Chrome on build-box       paired 2 Jun    last used 5 weeks ago   loopback

  The console needs no pairing and is not listed. Network listener: on.

Act on a device: 1-3   o) revoke all others   n) turn the network listener off   q) leave   ?   › 2
  2) Safari on iPad
Rename or revoke? r) rename   x) revoke   b) back   ?   › r
Label [Safari on iPad] › iPad Oliver
✓ Renamed: iPad Oliver
pm › web devices revoke 3
Revoke Chrome on build-box? It is signed out at once; its open pages close with the reason.
Revoke? [Enter]   b) back   ?   › ⏎
✓ Revoked: Chrome on build-box
pm › web devices revoke --others
Revoke 1 device other than this one (iPad Oliver)?
Revoke? [Enter]   b) back   ?   › ⏎
✓ Revoked 1 device; Firefox on mbp-oliver stays paired.
pm › web devices revoke 1
Revoke Firefox on mbp-oliver? It is the browser you are using on this machine:
  its pages close and show the pairing page; a new code pairs it again.
Revoke? [Enter]   b) back   ?   › ⏎
✓ Revoked: Firefox on mbp-oliver. web pair issues a new code.
pm ›
----

* `web devices` is the terminal side of link:../shared/paired-devices.adoc[Paired Devices]: the list (`devices.list`) with label, when paired and last used, from where (loopback or the network), and which one is _this one_; the acts (`devices.act`) rename, revoke one, revoke all others, and turn the network listener off (as `web disable`); a revocation (`devices.revoke`) voids the device's token at once and closes its open pages with the reason.
* _This one_ is the browser the console's entry paired or last opened on this machine; revoking it asks first and says that its pages land on the pairing page. Revoking any other device asks too, since it cannot be undone; `--yes` answers that confirmation in a script.
* The direct forms `web devices rename <device_id> <label>`, `web devices revoke <device_id>`, and `web devices revoke --others` act at once after the confirmation; the ids are the numbers of the list or the device ids the list shows with `?`.
