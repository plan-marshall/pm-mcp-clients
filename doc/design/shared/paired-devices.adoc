_Relies on: link:../../../../plan-marshall-documentation/doc/use-cases/02-entry.adoc#change-devices[Devices in Both Clients] (proposed); link:../../../../plan-marshall-documentation/doc/specification/cli-and-security/03-web-server.adoc#web-devices[Paired Devices]_

Status: `DRAFT`. Shared by both clients: link:../terminal-client/08-transcripts-later.adoc#t-devices[Terminal Client, Paired Devices], link:../web-app/README.adoc[Web App] (in its machine settings).

Every paired browser can do what the operator does: it is an operator channel. The list of paired devices is where the operator sees which browsers can act on the machine, and takes that right away from any of them. The terminal client needs no pairing and is never listed.

[#list]
== The List

----
  Paired devices · The browsers that can act on this machine
  ─────────────────────────────────────────────────────────────────────────────
    Firefox on mbp-oliver   paired 12 May   last used today 14:02   loopback   this one
    iPad Oliver             paired 20 May   last used 3 d ago       network
    Chrome on build-box     paired 2 Jun    last used 5 weeks ago   loopback
  ─────────────────────────────────────────────────────────────────────────────
  The terminal client needs no pairing and is not listed.
  Network listener: on                          [Turn the network listener off]
                                                       [Revoke all others]
----

* *A device* (`devices.list`): its label, when it was paired, when it was last used, from where it was last used (`loopback` or `network`), and `this one` for the browser the operator acts from; newest use first. A label is proposed at pairing from the browser and the machine it runs on, and the operator may rename it.
* *Its acts* (`devices.act`), one step away from its line: _Rename_ and _Revoke…_.
* *For the list*: _Revoke all others_ (every device but this one) and _Turn the network listener off_ (as `web disable`, link:../terminal-client/08-transcripts-later.adoc#t-devices[Terminal Client]); the listener's state is shown beside it.
* In the web app the list is reached from the machine settings (link:../web-app/README.adoc[Web App]); in the terminal client it is `web devices` with `rename <id> <label>`, `revoke <id>`, and `revoke --others` (link:../terminal-client/08-transcripts-later.adoc#t-devices[Terminal Client, Paired Devices]).

[#revoke]
== Revoking

----
  Revoke Chrome on build-box?
  ─────────────────────────────────────────────────────────────────────────────
  It is signed out at once; its open pages close with the reason.
                                                     [Keep it]  [Revoke it]
----

* *Every revocation asks first*, since it cannot be undone; a revoked device can only be paired again with a new code.
* *Revoking* (`devices.revoke`) voids the device's token at once and ends its event streams; the list shows it gone.
* *This device* asks with its consequence named: its pages close and show the pairing page, and a new code pairs it again. After the yes the web app deletes its stored secret and lands on the pairing page.
* *Revoke all others* names how many devices it revokes and which one stays.

[#revoked-page]
== A Revoked Page

An open page of a device that was revoked elsewhere, or expired after its idle time, does not fail silently: it shows why it can no longer act, and the way back.

----
  This browser is no longer paired
  ─────────────────────────────────────────────────────────────────────────────
  It was revoked from the terminal client today at 14:10.
  To use the web app here again, pair it with a new code: run pm-operator in a
  terminal of this machine.
                                                              [Pair this browser]
----

* The reason names who revoked it (the terminal client, or the label of another device) and when, or that it expired after not being used.
* Nothing the page showed stays visible behind the message.
