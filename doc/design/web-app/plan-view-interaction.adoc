[#layout]
== The Plan in the Column Model

The plan is a level of the chain of levels — the lens, the project, the epic, the plan, the task (link:navigation.adoc#levels[Navigation, Levels as Columns]) and takes the two forms of a level:

* *The object column*, while no task of it is open: the head of link:components-tags.adoc#tag-places[Tags and Kinds, One Fixed Place] (`KindMark`, title, id, pull request, the head links, `PhaseLabel`, `StatusLabel`, the state sentence, the `ActionBar`), the attention region, the lines _tokens so far_ and _change so far_, and the tabs *Process*, *Intent* and *Changes* (link:../shared/plan-view.adoc#tabs[Plan View, The Tabs of the Web App]). The head draws no path: the breadcrumb of the top bar is the only one (link:navigation.adoc#up[Navigation, Up, the Breadcrumb, Back]).
* *The attention region* is `ObjectPage`'s `attention` slot (link:components.adoc#object-page[Components, ObjectPage]), never the tabs': the attention strip that says what waits, the plan-level off-track banner, the line of a revision queued in the chat, and the ended plan's banner. A plan that has none of them leaves the region empty. The `state` slot carries phrasing content only, so a state line is a set of inline spans and never a block element.
* *The head opens objects in place*: a waiting plan's _Open the decision_ and an ended plan's _Completion report_ open beside the plan, as an object column of its own (`/plans/fix-relay?open=decision:Q-007`, `/plans/fix-relay?open=completion-report:fix-relay`; link:navigation.adoc#lenses[Navigation, Lenses and the Rail]). The object is opened by a push and closed by the history's back; closing an address that was loaded with `open=` replaces it with the plan's own address. A window with room for one column shows the object alone, the plan one Back away.
* *A list column*, while a task of it is open as the next level: the compact head (`KindMark`, title, state word, its main act as a secondary button) and the phase tree as its list. Selecting the plan's head closes the task, and the plan is the object column again with all its tabs. The list-column form and the task's own level are **PLAN-190**'s (`web-plan-task-level`); this page draws the object column.

----
  ▤ Plan  Fix Relay Transport                               [Pause the plan] [⋯]
  fix-relay  PR #214  ▶ execute  ● running · for 2 h 10 min · task 3 of 5
  tokens so far   412 k (380 k in · 32 k out)
  change so far   12 files · +340 −27 · 2 unplanned
  [Process]  Intent  Changes
  ┌ tree ────────────────────────────┬ narrative of the selected node ─────────┐
  │ ✓ init           done · 2 min    │ execute · running · 25 min              │
  │ ✓ refine         done · 14 min   │ tasks in this part                      │
  │ ▶ execute        running   ◀     │   TASK-001 · TASK-002 · TASK-003        │
  │   └ ▶ tasks envelope  running    │ parts in this part                      │
  │ ○ finalize       planned         │   envelope-ready · envelope-close       │
  └──────────────────────────────────┴─────────────────────────────────────────┘
----

* *The Process tab* holds the tree and the narrative of the node the tree points at. While the object column is at least `720 px` wide they stand side by side, the tree `280` to `360 px` wide and the narrative taking the rest; in a narrower column the narrative stands below the tree. The deepest chain leaves the object column below `720 px` on most windows (link:navigation.adoc#window[Navigation, The Column Window]), so side by side is the case of a shorter chain or a wide window, and stacking the usual one. Each keeps its own scroll. The width measured is the object column's own, never the viewport's. The tree's rows, the narrative's content and _Jump to now_ are **PLAN-62**'s; this page builds the tab's layout.
* *The Intent tab* shows the plan's intent record, its builder check and its outline in the order of link:../shared/intent-and-outline.adoc#intent[Intent and Outline] (<<intent>>).
* *The Changes tab* shows the plan's changes (<<changes>>); it is absent before the first capture, as the size line is. Its content (the file list and a file's hunks) is the `plan-changes` work package's; this page places the tab, its presence rule and the size line's link.
* *An ended plan* has the same tabs, read-only (link:../shared/plan-view.adoc#ended[Plan View, An Ended Plan]).

[#selection]
== Selection, Expansion, and Scrolling

There are three acts in the tree, and none of them stands in for another:

[cols="1,2,3",options="header"]
|===
|Act |Control |Effect

|Select a part
|the row body of a phase, sub-workflow, or task group, a native button
|The narrative shows that part. A row body never expands or collapses.

|Select a task
|the body of a leaf task row
|The task opens as the next level (`/plans/{id}/tasks/{task}`, a push): its object column shows the task's live activity and subscribes to its stream, and the plan becomes a list column whose list is this tree. The list-column form and the task's own level belong to **PLAN-190** (`web-plan-task-level`).

|Expand or collapse
|the chevron button beside the row of a node that has sub-nodes or tasks
|The children show or hide. A toggle never changes the selection or the narrative.
|===

* *A row*: the toggle (only where there is something to open), the state icon, then the row body with the kind drawn as its icon, the name, the state word and the duration. A leaf row has no toggle; its place stays free and the state icon stands where its siblings' does. The kind is an icon whose accessible name is the kind word (`role="img"`, the `state.node_kind.*` word); the row shows no kind word and no `↳`, and the name drops a leading kind word, so `phase execute` reads `execute`. A sub-node keeps its indentation.
* *A step the process did not take* (`not_taken`) is muted with the text-muted colour of the design system and keeps its state word, so the colour is never the only mark.
* *Catalogue words only*: the pruned group names each reason through `plan.prune.*` (`displayPruneReason`), and a task's status reads as its `state.task.*` word in the tree and the narrative (`displayState('task', …)`); a raw reason or status never reaches the screen, and one the catalogue has no word for reads as the unknown word. The catalogue is the only list of the prune reasons the client holds; the `PlanViewCatalogueTest` of `pm-api` keeps it complete against `PruneReason`.
* The row body is a `<button>` with an accessible name made of the node's own title and the catalogue's inspect action; the toggle is a sibling button with its own `aria-label` (`plan.view.toggle_node`, `plan.view.toggle_sub_node`). Buttons are never nested.
* `Enter` and `Space` select the focused row body; `Tab` moves between the toggle and the body. The selected row keeps the focus ring of the design system and the selected background.
* The selected row carries `aria-current` and the `node-row--selected` style; the row of the open task carries `aria-current` and `task-row--selected`.
* Only the open task's level subscribes to `subscribeTaskActivity`. Selecting a part in the tree of the plan's list column closes the task (a push, the plan the object column again, with the part's `node=` and without `follow=on`, which the selection ends: link:navigation.adoc#url[Navigation, Addresses]) and unsubscribes, so a hidden stream cannot keep appending to a column nobody sees.
* Ordinary selection does not scroll. Only the jump control expands the path to the current position, selects the running node, opens the running task where there is one, and scrolls that item into view.
* *Jump to now* is an `IconButton` of the tree's toolbar with the icon `nav.running`, named by `plan.path.jump` and explained by `plan.path.jump.title`; it scrolls the running node, or the node that waits for the operator, into view.

[#defaults]
== Opening, Defaults, and Refresh

* On a load without `node=` and without a task in the path, the selection is the node that holds the running task; if there is none, the running node; if there is none, the first visible node. The tree never opens with the narrative at “select something” while it shows at least one item. A task opens as a level only when the operator selects it, or under the follow mode (`follow=on`, link:navigation.adoc#url[Navigation, Addresses and History]).
* A refresh (`plan.changed`, `activity.changed`, `phase.changed`, `task.off_track`, `project.work_ended`) keeps the inspected subject when the refreshed tree still shows it — matched by task id or node id, never by list position. When the subject disappeared, or became `not_in_plan`, the same fallback order applies deliberately, and the address is replaced.
* Nodes omitted from the tree (`not_in_plan`) stay in the pruned group at the end and are not selectable. Their reason remains visible there.

[#node-narrative]
== What a Node Narrative Contains

A selected phase, sub-workflow, or task group narrates only what the process resource and its
child tasks already contain:

* *The head*: the part's title, its kind as the tree draws it (the icon named by the kind word), its localized state (with the run count where the plan ran it more than once), and its duration. `waits_for` is shown when the node carries it, and `prune_reason` through its catalogue word.
* *Tasks in this part*: one row per leaf task the node carries, including the tasks of its sub-nodes. Each row names the task id, role, harness and model, attempt, status, duration, tokens, and whether an activity route exists. Selecting a row opens that task as the next level.
* *Parts in this part*: the direct sub-nodes as a compact outline with their state. Selecting one selects it in the tree, so the operator can walk down the tree from the narrative as well as from the tree.
* *Refine and outline*: the narrative of these two phases links to the Intent tab (_Intent_, `intent.tab.title`), where their records stand.
* *No invented summary*: a node narrative never aggregates free-text activity into a fabricated phase summary, never adds a state the process did not report, and never fetches anything the plan view did not already load.

[#empty-states]
== The Three Empty States

[cols="1,2,2",options="header"]
|===
|Situation |What the narrative says |Key

|Nothing is selected
|Select a part or a task in the tree to inspect it.
|`plan.activity.select_item`

|A selected part carries no leaf tasks
|This part has no task-level activity. Its state and duration are shown above.
|`plan.node.no_activity`

|An open task has no activity entries
|No activity entries yet.
|`plan.activity.empty`
|===

The three states are distinct on purpose: “nothing selected” is not a property of a part, and a
part that completed without tasks is not a task with an empty feed.

[#intent]
== The Intent Tab

The tab shows the records of link:../shared/intent-and-outline.adoc#web[Intent and Outline, The Web App]: the intent, the builder check and the outline, in that order, one below the other, each reference one step away. Before refine has submitted a record the tab says so (`intent.plan.none`) and shows no empty sections.

[#changes]
== The Changes Tab

The size line of the head is a link to this tab (link:../shared/plan-view.adoc#changes[Plan View, The Changes]): the list of files, and a selected file's hunks on `--color-diff-removed` and `--color-diff-added`, in `--font-mono`, the same diff tokens as a proposal of the chat (link:components-chat.adoc#proposal-card[Chat Pieces, Proposal Card]). The list and the hunks follow the rule of the Process tab: side by side while the object column is at least `720 px` wide, the list `280` to `360 px` wide and the hunks taking the rest; in a narrower column the hunks stand below the list. The tab is absent before the first capture; an address that names it then opens the first tab and is replaced.

[#addresses]
== Addresses

The plan's tab is `tab={id}` (`process`, `intent`, `changes`; link:navigation.adoc#url[Navigation, Addresses and History]); an address without it opens _Process_.

* *A key per tab*: `node={path}` belongs to _Process_ and `file={path}` to _Changes_ (`/plans/fix-relay?tab=changes&file=pm-relay/pom.xml`), and each is written only while its tab is shown.
* *Selecting a node* in the tree or in the narrative's outline writes `node=` by a replace (`selectPlanNode`); selecting a task writes no `node=` and drops the one a node selected earlier left in the address, together with the node the view remembers for the open plan, so the address never names a node the view no longer shows (the jump to a running task is such a selection). A load with `node=` naming a node the tree shows opens on that node, ahead of the default order (<<defaults>>); one naming no shown node falls back to it. The node of a load stays the plan's selection whatever read delivers it: when a process event supersedes the initial read, the first read that is accepted applies the address, and a load that names another tab with `tab=intent&node=…` records the node without leaving that tab.
* *Switching the tab* replaces the address and drops the other tab's key; the view keeps the other tab's selection in memory while the plan stays open, so going back to that tab shows it again — the Changes tab writes the remembered `file=` back into the address it shows, and the Process tab the remembered `node=`. The remembered node belongs to the open plan: opening another plan drops it.
* *An object in place* is `open={kind}:{id}` on the plan's own address: `decision` with the decision's id, and `completion-report` with the plan's id (link:navigation.adoc#url[Navigation, Addresses and History]).
* *A task* is a level (`/plans/{id}/tasks/{task}`) and carries no tab of the plan.

[#safety]
== Untrusted Text

`title`, `waits_for`, `prune_reason`, sub-node titles, task labels, activity content, paths and
diff lines are untrusted text from the runtime. They are rendered as text after
`stripControlSequences`, never with `{@html}`, and never turned into links the client follows. The
narrative inherits the same trust boundary as the existing activity feed
(link:../shared/plan-view.adoc#worker[Plan View, A Worker at Work]).

[#decisions]
== Decisions of the Operator

Settled by the operator on 2026-11-10 (D6): the plan is the object column with the tabs Process, Intent and Changes, and a list column whose list is the tree while a task is open; the tokens stay the one-step disclosure of the head line, and there is no Activity, Tokens or Settings tab (_Plan settings…_ stays a dialogue, link:../shared/work-actions.adoc#plan-actions[Work Actions, Plan Actions]); the changes are a tab rather than a disclosure; tree and narrative stand side by side from an object column of `720 px`; `node=` and `file=` are written only with their tab.
