[#overview]
== Overview and Problem Statement

The web app supports both light and dark themes, chosen in the header as light, dark, or system, and remembered per browser. `system` follows the browser's `prefers-color-scheme`; an explicit choice overrides it, and the choice is applied before the first paint. During operation against running mock scenarios, three systemic readability defects were observed:

. **Findings review action readability in dark mode (F1):** The epic findings review button (`.review-open`, labelled "Review" or "Prüfen") rendered with `rgb(0, 0, 0)` on a dark card background (`rgb(19, 27, 46)`), resulting in an unacceptable 1.22:1 contrast ratio. The root cause was an incomplete button reset in `base.css` (`button { background: none; }` without `color: inherit;`), causing standard `<button>` elements without explicit color to fall back to the browser's default black text.
. **Undefined CSS token references (F2):** Five color tokens (`--color-accent`, `--color-accent-hover`, `--color-bg-base`, `--color-bg-subtle-hover`, `--color-warning-text`) were referenced in views and components but never declared in `tokens.css`.
. **Hard-coded color literals and light-only palettes (F3):** Over 130 hard-coded hex and rgba color literals were embedded in Svelte components and scoped styles, alongside fragile fallback patterns (`var(--token, #hex)`) that prevented dark mode from adapting effectively.

[#token-contract]
== The Design Token Contract

The tokens of design system v2 are declared in `pm-web-app/src/styles/tokens.css`, following link:../../claude_review/visual-design/proposals.adoc#VD-P-02[VD-P-02] to link:../../claude_review/visual-design/proposals.adoc#VD-P-04[VD-P-04]. `:root` carries the scale every theme shares and the light palette as the default; `@media (prefers-color-scheme: dark) :root`, `[data-theme="light"]` and `[data-theme="dark"]` override the palette. The three theme blocks declare the same set of theme-varying keys and `:root` holds every one of them, and `pm-web-app/src/styles/tokens.test.ts` asserts both directions.

* `--color-brand`, dark: `#7C6CF6` → `#8B7EF9`. At the proposed value the brand reached 4.39:1 as link text on `--color-bg-surface` and 3.94:1 on `--color-bg-subtle`, below the 4.5:1 normal-text threshold.

=== Type Scale

The scale of VD-P-03 is declared as size, line height and weight. The sizes are the px of the proposal as rem equivalents at the 16 px root, so a larger browser font size scales the interface.

Each size carries its line height as `--line-height-xs` to `--line-height-3xl`; the weights are `--weight-regular` (400), `--weight-medium` (500) and `--weight-semibold` (600). The interface runs on the self-hosted Inter variable font (`pm-web-app/static/fonts/InterVariable.woff2`, its SIL Open Font License beside it as `OFL.txt`), with `font-feature-settings: "tnum" 1, "cv11" 1` for tabular numerals. Inter is named first in `--font-sans`, and the system stack follows as the fallback.

=== Spacing, Radius, Elevation, Motion and Breakpoints

* *Spacing*: `--space-1` to `--space-16` on the 4 px scale of VD-P-04, including the new 48 px (`--space-12`) and 64 px (`--space-16`).
* *Radius*: `--radius-sm` 6 px, `--radius-md` 8 px, `--radius-lg` 12 px, `--radius-full`.
* *Elevation*: `--shadow-1` (cards in light), `--shadow-2` (popovers), `--shadow-overlay` (dialogs). In dark, elevation is the surface step and the shadows stay faint; each of the three is declared per theme.
* *Motion*: `--duration-fast` 120 ms, `--duration-base` 200 ms and `--ease-standard` `cubic-bezier(0.2, 0, 0, 1)`; `prefers-reduced-motion: reduce` sets both durations to `0ms`, and `base.css` shortens a component's own animation as well.
* *Breakpoints*: `--breakpoint-tablet` 768 px and `--breakpoint-desktop` 1280 px name the three widths of the proposal: phone below 768 px, tablet 768–1279 px, desktop from 1280 px.

=== Old Token Names as Aliases

During the migration every v1 token name stays declared once in `:root` as `var(--<v2 token>)`, so a view that still names `--color-primary`, `--color-warning`, `--shadow-sm` or any other v1 name renders the v2 value of its theme. The two mappings the proposal states are `--color-primary: var(--color-brand)` and `--color-warning: var(--color-attention)`; a pair of the same kind exists for every v1 name. `--color-star` maps onto `--color-attention-text`, because the favourite star renders as text and the attention dot colour does not meet the normal-text threshold on a light surface. `pm-web-app/src/styles/tokens.test.ts` asserts every mapping; VD-S-08 removes them.

=== Base Reset Invariant

All interactive elements (`button`, `input`, `select`, `textarea`) in `pm-web-app/src/styles/base.css` must declare:

[source,css]
----
button,
input,
select,
textarea {
  font-family: inherit;
  font-size: inherit;
  line-height: inherit;
  color: inherit;
}

button {
  cursor: pointer;
  background: none;
  border: none;
  padding: 0;
  color: inherit;
}
----

This invariant ensures that unstyled buttons inherit foreground colors from their surrounding theme container rather than reverting to user-agent default black text in dark contexts.

[#contrast-thresholds]
== Contrast Thresholds & Relative Luminance

All user-visible textual elements adhere to the Web Content Accessibility Guidelines (WCAG) 2.1 Level AA:

* **Normal Text (< 18pt or < 14pt bold):** Minimum contrast ratio of **4.5:1** against the effective composited background.
* **Large Text (>= 24px or >= 18.66px with weight >= 700):** Minimum contrast ratio of **3.0:1** against the effective composited background.

=== Alpha Compositing Engine

In modern web applications with layered cards, elevated panels, and modal overlays, backgrounds are frequently semi-transparent (`rgba(...)`). The contrast analyzer (`pm-web-e2e/tests/helpers/contrast.js`) walks the DOM ancestor tree from the target element up to `document.documentElement`, collecting non-transparent background layers and compositing them via the Porter-Duff source-over formula:

\[
C_{\text{composite}} = C_{\text{layer}} \times \alpha_{\text{layer}} + C_{\text{underlying}} \times (1 - \alpha_{\text{layer}})
\]

Relative luminance is computed using the standard sRGB linearisation curve:

\[
L = 0.2126 \times R_{\text{linear}} + 0.7152 \times G_{\text{linear}} + 0.0722 \times B_{\text{linear}}
\]

Contrast ratio between two luminances \(L_1\) (lighter) and \(L_2\) (darker) is defined as:

\[
\text{Ratio} = \frac{L_1 + 0.05}{L_2 + 0.05}
\]

[#audit-allowlist]
== The Audit Allowlist

Only one reasoned, functional exception is permitted to use hard-coded color literals:

* **`PairingQr.svelte`:** SVG QR code modules use `#ffffff` (quiet zone and light modules) and `#000000` (dark modules). QR code optical scanners require strict binary black-on-white module contrast regardless of operating system or browser theme.

All other components and views must reference defined tokens in `tokens.css`. Static scans in `tokens.test.ts` enforce zero unexpected color literals across `pm-web-app/src/lib/`.

The contrast audit itself exempts nothing: `CONTRAST_ALLOWLIST` in `pm-web-e2e/tests/theme-readability.spec.js` is empty, so every text and state pair a view renders is judged. An entry added later names the selector it exempts and the reason the pair cannot meet the threshold; a guard test in the same file fails an entry that states no reason.

[#verification-matrix]
== Automated Verification Matrix

The test pyramid enforces theme readability across three automated tiers:

. **Static & Token Unit Tests (`pm-web-app/src/styles/tokens.test.ts`):**
  * Verifies exact key parity between `:root`, `[data-theme="light"]`, `@media (prefers-color-scheme: dark)`, and `[data-theme="dark"]` for every token of VD-P-02.
  * Asserts the type scale of VD-P-03, the spacing, radius, elevation, motion and breakpoint tokens of VD-P-04, and every old token name as an alias of its v2 token.
  * Audits the WCAG 2.1 AA contrast of the declared pairs in both themes: every text pair at 4.5:1 or above, every state dot at 3:1 or above.
  * Parses all `.svelte` and `.css` files to ensure every `var(--...)` reference exists in the token catalogue.
  * Static regex scanner asserting zero hard-coded `#hex`, `rgb()`, or `hsl()` literals outside the documented `PairingQr.svelte` allowlist.

. **Component Theme Tests (`pm-web-app/src/lib/views/theme.test.ts`):**
  * Mounts representative components (`EpicView`, `OverviewView`, `FindingsReviewModal`) under `data-theme="light"` and `data-theme="dark"`.
  * Asserts computed token styles, classes, and explicit readability on the "Prüfen" action button and modal dialogs.

. **Playwright E2E Theme Matrix (`pm-web-e2e/tests/theme-readability.spec.js`):**
  * Runs against the live `pm-mock-runtime`.
  * Verifies both light and dark themes across desktop (1280×800), mobile (375×667) and narrow (320×568) viewports.
  * Audits every visible element's computed contrast ratio across `OverviewView`, `EpicView`, `PlanView`, `ReportsView`, `DecisionView`, `SystemView`, `CleanupView`, `SettingsView`, `MachineSettingsView`, `ProcessDesigner`, `ProjectExplorerView`, the onboarding views, the entry views and the decomposition views.
  * Captures passing visual evidence and screenshots for both themes.

The self-hosted face has its own tier in `pm-web-e2e/tests/fonts.spec.js`: the browser fetches Inter from the app's own origin, requests no font service, and reads the SIL Open Font License beside the file.
