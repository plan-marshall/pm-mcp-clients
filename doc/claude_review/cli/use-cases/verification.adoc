== How to Verify

Each step of link:plan.adoc[the plan] is verified in three ways:

. *Unit tests* of `pm-operator`: `./mvnw -pl pm-operator verify`.
. *PTY tests* (`*IT` in `transcript/`): `./mvnw -pl pm-operator verify -Pintegration-tests`, against the mock started
  by the test (`MockRuntime.start`).
. *A walk in a real terminal* against the running mock:
.. Start `pm-mock-runtime/start.sh --scenario <name> --web-port 7420`.
.. Run `PM_MCP_BASE=pm-mock-runtime/target/machine pm-operator/start.sh <verb>` in an operator terminal.
.. Jump with `curl -X POST http://127.0.0.1:7420/mock/goto/<state>`.
.. Compare the screen with the check below, in `en_US.UTF-8` and `de_DE.UTF-8`, at 120 × 30 and 80 × 24.

A step is done when all its checks pass and the matrix in link:analysis.adoc#matrix[Analysis] moves the use cases to
`conforms`.

== Regression Guard

Add one PTY test per dialogue that acts (pause, cancel, answer, waiver, onboarding, project setup, cleanup, runtime
stop). Each test types `q` first and asserts that the mock received no act (`GET /mock/state` and the event log), then
runs the main path. This guard protects every step of this plan (check CLI-CC-V-06 of link:../cross-cutting/verification.adoc[Cross-Cutting, Verification]).
