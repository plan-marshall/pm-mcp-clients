== Result in Short

The terminal client has two faces:

. *The printed verbs are fast.* `status`, `epic <id>`, `system`, `reports`, and `questions` each answer one question in
  one screen, with no key to learn. For a production operator this is the strongest part of either client.
. *The interactive parts are fragile.* The help key breaks every full-screen view. The footer keeps text of the level
  before. Dialogues have no way out or no question at all. Errors are HTTP codes and JSON. The operator cannot trust
  what a key or an answer will do.

[#model]
== Interaction Model Today

[source,text]
----
pm-operator <verb>           printed result, exit code         status, epic, system, reports, projects --list
pm-operator                  console  pm ›                     help, questions, answer, plans, any verb
  plans | tui | projects     full-screen views (alternate screen)
    Running work · projects ─ project (by plan | by epic) ─ plan view ─ worker activity
                            └ E ended work   R reports   S system   a actions   ! what waits   ? help
  dialogues                  line mode in the scrollback       start, pause, cancel, chat, answer, config
----

Observations:

* *Three surfaces, three key languages.* Verbs take options, the console takes verbs, the views take single keys, and
  dialogues take a key plus Enter. `q` leaves a view, prints a usage dump at the console prompt, and pauses a plan in
  the pause dialogue.
* *Verb modes differ by verb.* In a terminal, `plan <id>` opens full screen; `epic <id>` prints; `system` prints in the
  shell and opens full screen in the console.
* *Discoverability.* The console `help` lists 9 of the 29 verbs. The shell has no `help` verb (`pm-operator help` is a usage
  error). The full-screen help overlay does not work.

[#direction]
== Direction

* *Printed first.* Keep the printed verbs as the fast path, and make each one complete: `needs` (what needs me),
  `status`, `epic`, `plan --print`, `system`, `reports`.
* *One dialogue contract.* Every dialogue that acts uses the strict choice prompt: a question, numbered or lettered
  choices, the preselection marked, `?` explains, `q` leaves, unknown input re-asks.
* *One key language in views.* The footer is complete, never stale, and `?` shows all keys.
* *One error pattern.* `✗` line, cause in words, `→ fix`, and the exit code of `01-commands.adoc`.
* *Scripts are users.* `--json` on every listing verb, with stable fields, documented.
