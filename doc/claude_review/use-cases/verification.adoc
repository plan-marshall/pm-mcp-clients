== How to Verify

Each step of link:plan.adoc[the plan] is verified in three ways:

. *Unit tests* in `pm-web-app` (`npm test` through Maven: `./mvnw -pl pm-web-app verify`).
. *E2E specs* in `pm-web-e2e` (`./mvnw -pl pm-web-e2e verify -Pintegration-tests`), against the mock.
. *A walk in Chrome* against the mock:
.. Start `pm-mock-runtime/start.sh --scenario <name> --web-port 7420` and the Vite dev server.
.. Pair the browser.
.. Jump with `curl -X POST http://127.0.0.1:7420/mock/goto/<state>`, then reload.
.. Compare the screen with the check below.
.. Repeat in `de` and `en`, dark and light, at 1440 px and 390 px.

A step is done when all its checks pass and the matrix in link:analysis.adoc#matrix[Analysis] moves the use cases to
`conforms`.

== Regression Guard

The e2e spec `theme-readability.spec.js` already proves that every declared view is covered. Extend it with one
assertion per view: the rendered text contains no raw enum (`/\b[a-z]+_[a-z_]+\b/`), no state id, no `{placeholder}`,
and no ISO time string (`/\d{4}-\d{2}-\d{2}T/`). This guard is the cross-cutting check CC-V-01 and protects every step
of this plan.
