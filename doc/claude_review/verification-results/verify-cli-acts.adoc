`CLI-UC-V-10` (the operator's agreement is not a check a plan can run); each of those parts is `not verified` with its
reason. Three checks carry a `fail`, each routed as one finding to the epic inbox. Nothing that was found was fixed.

[#results]
== What the Checks Found

Three checks fail and are routed, each as one `finding` message to the epic inbox of `ui-improvements`:

. *`CLI-UC-V-06`*: `onboard --auto --yes` is not a verb of `pm-operator` (exit `2`, `Unmatched arguments from index 0`);
the automatic onboarding now starts from the entry's first choice. The check as written cannot hold. Plan concerned:
PLAN-22 (one state dialogue for both onboardings).

. *`CLI-UC-V-09`*: `plan nope` prints `Plan nope not found.`, not `No plan nope`, and the full-screen overview prints
`Nothing runs` when the projects read is refused. Plan concerned: PLAN-20 (action menus by state) for the overview
defect; the refusal text belongs to PLAN-30, which has not landed.

. *`CLI-CC-V-06`*: the regression guard names the waiver beside the answer dialogue, and the waiver path has only its
main path in `AnswerDialogueIT` — no `q`-first and no unknown-input case — so `q` sending nothing is unproven there.
Plan concerned: PLAN-21 (the working answer dialogue), whose dialogue the waiver path belongs to.
