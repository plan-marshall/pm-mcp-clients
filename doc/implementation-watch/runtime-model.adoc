== Relay

[#PM-WATCH-RUN-16]
=== PM-WATCH-RUN-16: The listen stream stays silent and `initialize` issues no session

Anchor:: link:../specification/runtime-model/03-relay.adoc#_harness_protocol_forms[Runtime Model § Harness Protocol Forms],
link:../../../plan-marshall-documentation/doc/Requirements.adoc#PM-ARCH-3[PM-ARCH-3], link:../../../plan-marshall-documentation/doc/Requirements.adoc#PM-SKILL-2[PM-SKILL-2]
Hazard:: The Quarkus MCP server declares `tools.listChanged: true` and acknowledges `subscriptions/listen` with a stream
that stays open for the whole session without a final response. The runtime's surface is fixed per connection, so a
message on that stream, or a list-changed notification anywhere, makes a harness list again for nothing; a listen that
gets no answer at all blocks Claude Code's start for 27 s (the server acknowledges at once, so this arises only
where something in front of it withholds the acknowledgement). A runtime restart ends the listen stream of every
open session. Equally, the `Mcp-Session-Id` the server attaches to every `initialize` response turns a
session-opening harness into a session-holding one.
Guard:: Test pinning both: a `subscriptions/listen` is acknowledged at once, the runtime sends nothing more on its
stream, and tool calls on other requests are served while it is open; no list-changed notification is ever emitted,
on a listen stream or on a call's response; the `initialize` response carries no `Mcp-Session-Id`, also for a
request that arrives without the `Mcp-Method` header (the method read from its body), and a following request
without a session is served; a `server/discover` without the protocol keys in `_meta` is refused `400`. A dependency
upgrade of `quarkus-mcp-server` re-runs the test before it lands. Each harness is run across a runtime restart with its
listen stream open before the always-on runtime ships: it opens the listen again or goes on without it; for a harness
that fails, the relay answers the listen locally and keeps it open across runtime restarts.
Fixture:: An open listen stream stays silent across two tool calls made on other requests. Claude Code: 27 s start
delay with an unanswered listen; a listen refused with `-32601` is retried three times at +1, +3, +7 s, then no
more; all tools usable in both cases.
Source:: link:../../../plan-marshall-documentation/doc/specification/evaluation.adoc#results[Evaluation Reference], Gate 10.

[#PM-WATCH-RUN-10]
=== PM-WATCH-RUN-10: A harness cancel of an answered request cancels nothing

Anchor:: link:../specification/runtime-model/03-relay.adoc#relay-rules[Runtime Model § Relay Rules] (rule 4),
link:../../../plan-marshall-documentation/doc/Requirements.adoc#PM-ARCH-3[PM-ARCH-3]
Hazard:: OpenCode sends `notifications/cancelled` for every request it has already received an answer for;
treated as the cancel of pending work, each such notification cancels the wait or the job that the answer started.
Guard:: Relay and runtime fixtures: a cancellation whose `requestId` the relay has already answered is dropped and
never forwarded; the runtime ignores a cancellation of a request it has answered; a cancellation of a pending
`pm_wait` ends only that call without consuming or leasing a task; no cancellation ends a job; matched control: a
cancellation of a pending `pm_build` wait ends that wait and leaves the build running.
Source:: harness-as-worker evaluation (link:../../../plan-marshall-documentation/doc/specification/evaluation.adoc[Evaluation Reference]).

[#PM-WATCH-RUN-11]
=== PM-WATCH-RUN-11: Identity arguments never appear in a tool schema

Anchor:: link:../specification/runtime-model/03-relay.adoc#relay-rules[Runtime Model § Relay Rules] (rule 5),
link:../../../plan-marshall-documentation/doc/Requirements.adoc#PM-ARCH-3[PM-ARCH-3]
Hazard:: With the worker identity, generation, and role visible as tool arguments, the OpenCode model filled them
with invented values and kept them in its compaction summary; after a compaction a model passed an invented
worker id remembered from an earlier run.
Guard:: A `tools/list` through the worker relay, for a worker of every harness, contains no property of
the identity set (`generation_id`, `role`, `worker`, `job_token`) in any `inputSchema`; a `tools/call` carrying such an
argument reaches the runtime without it; the runtime's own tool schemas declare none, and identity, role, and
generation are taken only from the relay's headers; matched control: a call whose header identity differs from an
invented argument is bound to the header identity.
Source:: harness-as-worker evaluation (link:../../../plan-marshall-documentation/doc/specification/evaluation.adoc[Evaluation Reference]).
