== Runtime Access & On-Demand Start

[#PM-WATCH-RUN-1]
=== PM-WATCH-RUN-1: Started means reachable

Anchor:: link:../specification/cli-and-security/01-cli-and-installer.adoc#cli-daemon-access[CLI & Security § Runtime Access & On-Demand Start],
link:../../../plan-marshall-documentation/doc/Requirements.adoc#PM-ARCH-7[PM-ARCH-7]
Hazard:: A daemon start reported `running` before liveness was verified.
Guard:: Every on-demand start by `pm-operator` and `pm-operator status` report `running` only after a
successful authenticated round trip on the runtime's socket (runtime token); `status` is an API request, so its
`running` is that round trip, and `state/runtime.json` serves only the "not running" answer (no live record) without
starting the runtime; a test kills the runtime during start, and another leaves a `runtime.json` of a dead process
and a stale `runtime.token`.
Source:: plan-marshall defect truthful-signals PLAN-TRUTH-150 D8.

[#PM-WATCH-RUN-5]
=== PM-WATCH-RUN-5: Without a runtime, the runtime-free verbs start nothing and write nothing

Anchor:: link:../specification/cli-and-security/01-cli-and-installer.adoc#cli-daemon-access[CLI & Security § Runtime Access & On-Demand Start],
link:../../../plan-marshall-documentation/doc/Requirements.adoc#PM-ARCH-7[PM-ARCH-7]
Hazard:: A status query, a harness status check, or a drain that silently brings up the runtime or writes a file
breaks the single-writer rule and turns a read-only check into a state change.
Guard:: With no runtime running, each command of the closed list
(link:../specification/cli-and-security/01-cli-and-installer.adoc#cli-without-runtime[CLI & Security § Without the runtime])
runs against a `PM_MCP_BASE` whose tree is hashed before and after: no runtime process is started,
no socket exists afterwards, and the tree is byte-identical (contents, names, and modes), and each verb opens only
files of the closed list of direct file reads; matched control: each command of the on-demand list (a `pm-operator` command
that sends an API request, and `pm-operator runtime start`) starts the runtime on demand; negative control: the worker relay `pm-mcp serve --job`
started without a runtime starts no runtime process.
Source:: design review.

== Relay

[#PM-WATCH-RUN-10]
=== PM-WATCH-RUN-10: A harness cancel of an answered request cancels nothing

Anchor:: link:../specification/runtime-model/03-relay.adoc#relay-rules[Runtime Model § Relay Rules] (rule 4),
link:../../../plan-marshall-documentation/doc/Requirements.adoc#PM-ARCH-3[PM-ARCH-3]
Hazard:: OpenCode sends `notifications/cancelled` for every request it has already received an answer for;
treated as the cancel of pending work, each such notification cancels the wait or the job that the answer started.
Guard:: Relay and runtime fixtures: a cancellation whose `requestId` the relay has already answered is dropped and
never forwarded; the runtime ignores a cancellation of a request it has answered; a cancellation of a pending
`pm_wait` ends only that call without consuming or leasing a task; no cancellation ends a job; matched control: a
cancellation of a pending `pm_build` wait ends that wait and leaves the build running.
Source:: harness-as-worker evaluation (doc/specification/evaluation.adoc).

[#PM-WATCH-RUN-11]
=== PM-WATCH-RUN-11: Identity arguments never appear in a tool schema

Anchor:: link:../specification/runtime-model/03-relay.adoc#relay-rules[Runtime Model § Relay Rules] (rule 5),
link:../../../plan-marshall-documentation/doc/Requirements.adoc#PM-ARCH-3[PM-ARCH-3]
Hazard:: With the worker identity, generation, and role visible as tool arguments, the OpenCode model filled them
with invented values and kept them in its compaction summary; after a compaction a model passed an invented
worker id remembered from an earlier run.
Guard:: A `tools/list` through the worker relay, for a worker of every harness, contains no property of
the identity set (`generation_id`, `role`, `worker`, `job_token`) in any `inputSchema`; a `tools/call` carrying such an
argument reaches the runtime without it; the runtime's own tool schemas declare none, and identity, role, and
generation are taken only from the relay's headers; matched control: a call whose header identity differs from an
invented argument is bound to the header identity.
Source:: harness-as-worker evaluation (doc/specification/evaluation.adoc).

== The Encoder of `pm-api`

[#PM-WATCH-RUN-18]
=== PM-WATCH-RUN-18: Hidden characters are filtered in the encoder, never in the store

Anchor:: link:../specification/runtime-model/06-event-catalogue.adoc#client-text-hidden-characters[Runtime Model § No Hidden Character Reaches a Client],
link:../../../plan-marshall-documentation/doc/Requirements.adoc#PM-SEC-1[PM-SEC-1]
Hazard:: A filter applied per resource misses the next path a text takes to a client (an error's detail, an event's
argument, a chat delta, a resource added later), and a filter applied when a record is written hides from the
added-line scan, the outbound text check, and the audit trail the very characters they exist to see.
Guard:: A contract test of `pm-api` over every resource type and every event of the catalogue that carries a string:
a value holding a right-to-left override, a zero-width space, a tag character, `ESC`, and a lone surrogate arrives
without them, in the real runtime's answers and in the mock runtime's; line feed and tab survive; matched control:
the stored record read back holds the characters, and the added-line scan reports a plan line holding one.
Source:: link:../../../plan-marshall-documentation/doc/articles/web-scam-defenses.adoc[Google's web scam defenses analysis] (ClickFix: what is copied
is not what is shown).
