== What

A workflow unit is written in the language of the workflow DSL, which no model has seen in its training. The author most likely to write one in a project's repository is a coding agent working for the operator; without the runtime's validation it learns about an invented keyword or a wrong parameter only when a plan fails at its next phase handshake with `config_invalid`. This package gives that author the runtime's own check in the terminal.

* *Design first*: the package designs the verbs and their texts in link:../design/terminal-client/01-commands.adoc[Terminal Client, Commands] (the bullet _No designer_ changes: the terminal still has no designer, but validates and lists the catalogue) and has the operator accept it before building it.
* A verb that validates a unit file the operator or an agent names, for the machine or a project, through the validation endpoint of `designer-contract`: every stage (frontmatter, parse, static rules, compiled invariants, dry run against the project or every project it would reach), each finding with its rule or invariant, its line, and its column; a valid unit with the composed process as a short summary.
* A verb that lists the catalogue of the machine or a project: the building blocks with the template each inserts, filterable by kind and name, so that an author takes the vocabulary from the runtime instead of guessing it.
* Both print for a person and, on request, machine-readable (one stable form, its fields named in the design), and exit non-zero when a unit has findings, so that a coding agent or a pre-commit hook can use them; both change nothing and write no audit record. Placing and removing stay in the web app.
* Texts from the message catalogue only.
