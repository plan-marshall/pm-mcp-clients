== What

A thorough logical design of `pm-operator` as the operator's second client, reviewed by the operator before any implementation:

* *Command model*: the command tree with the new verbs (`start`, `onboard`, `config <aspect>`), their arguments, and the rule that command names and options are the same in every language; how a direct verb runs a sub-workflow and stops at the first choice it was not given.
* *Levels*: how the terminal shows and addresses the levels of configuration (machine, project, plan) and a running plan; how a value shows where it comes from (default, machine, project, plan) and what overrides it; how the operator picks a project or plan to act on.
* *Dialogues*: the rendering of a state (step line, content, links as keys or numbers, preselection on `Enter`, `?` for the explanation), consent, check lists with checkmark or error, waiting and progress, interruption and resume, non-interactive use and `--json`.
* *Texts*: every text of the onboarding and of `start` as keys of the catalogue with the English and the German text.
* *Transcripts*: a terminal transcript for every state of the onboarding and of `start`, complementing the web wireframes of the design.

== How It Is Run

This package is design work and is run directly in a Claude Code session, without plan-marshall and outside the orchestrator epic:

. Start a Claude Code session in a worktree of `plan-marshall-documentation` of its own (beside the checkouts other sessions use) and give it this file: "Work the package `cli-design` of `pm-mcp-clients` (`doc/plans/cli-design.adoc`)".
. The session reads the use cases, the design documents, and the specification sections of the trace above, works out the design thoroughly, and opens one pull request in `plan-marshall-documentation` with the design document in `doc/design/`.
. The operator reviews the design in that pull request and asks for changes until it accepts it; the session merges only on the operator's word.
. Once accepted, a small pull request here sets the row of the package to `done` in the index; the implementation packages that wait on it become ready.
