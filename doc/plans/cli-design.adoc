== What

A thorough logical design of `pm-operator` as the operator's second client, reviewed by the operator before any implementation:

* *Command model*: the console `pm-operator` as the entry, its commands, and `config <aspect>`, their arguments, and the rule that command names and options are the same in every language; how a direct verb runs a sub-workflow and stops at the first choice it was not given.
* *Levels*: how the terminal shows and addresses the levels of configuration (machine, project, plan) and a running plan; how a value shows where it comes from (default, machine, project, plan) and what overrides it; how the operator picks a project or plan to act on.
* *Dialogues*: the rendering of a state (step line, content, links as keys or numbers, preselection on `Enter`, `?` for the explanation), consent, check lists with checkmark or error, waiting and progress, interruption and resume, non-interactive use and `--json`.
* *Console*: the prompt, pushed questions and how they are answered, deadlines, answers given elsewhere, connection, keys, notifications, and the line editor.
* *Texts*: every text of the onboarding, the entry, and the console as keys of the catalogue with the English and the German text.
* *Transcripts*: a terminal transcript for every state of the onboarding and of the entry, and of the console at work, complementing the web wireframes of the design.

== Done When

The design document is merged in this repository and the operator has accepted it, and the corrections of the use cases it needed are merged in `plan-marshall-documentation`; every state of the onboarding, of the entry, and of the console has its transcript and its texts in both languages; every open point is decided or listed with its owner.

== How It Is Run

This package is design work and is run directly in a Claude Code session, without plan-marshall and outside the orchestrator epic:

. Start a Claude Code session in this repository, with a worktree of `plan-marshall-documentation` of its own for the use-case corrections (beside the checkouts other sessions use), and give it this file: "Work the package `cli-design` of `pm-mcp-clients` (`doc/plans/cli-design.adoc`)".
. The session reads the use cases, the design documents, and the specification sections of the trace above, works out the design thoroughly, and opens a pull request here with the design document in `doc/design/`, and one in `plan-marshall-documentation` with the corrections of the use cases the design needs.
. The operator reviews the design in the pull request here and asks for changes until it accepts it; the session merges only on the operator's word, the use-case corrections first.
. Once accepted, the pull request here sets the row of the package to `done` in the index in a last commit; the implementation packages that wait on it become ready.
