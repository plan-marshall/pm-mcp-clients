== What

* *Specification first*: the package writes the changes of UC-PLN-4 into `plan-marshall-documentation` as part of its own work (link:../../../plan-marshall-documentation/doc/discussions/client-specification-changes.adoc#slicing[Specification Changes for the Clients, Packages]), once the use case is agreed, and opens that pull request beside its own; the proposal's rows it writes are removed from the proposal.
* The resource records of the overview in `pm-api`: the projects with running work (`GET /api/v1/projects`) and one project with its active plans and orchestrators (`GET /api/v1/projects/{project_id}`), each with its `needs_operator` summary (closed kinds), counts, titles and names, `created_at`, `phase_entered_at`, progress, and a plan's orchestrator; as the specification of the changes of UC-PLN-4 defines them.
* The event types the overview follows (running work gained or lost, a plan or orchestrator started or ended, a phase change, a condition raised or cleared, an orchestrator's plan changing status, an item held for the operator), with their payloads and the codec.
* The routes and scenarios of the mock runtime for the overview: an empty machine, projects with and without work that needs the operator, a project with orchestrators and plans without one, a plan ending while it is selected, a lost connection; scenario names `overview-<case>`.

== Done When

The specification of the changes of UC-PLN-4 is merged in `plan-marshall-documentation`; every record and event type has a round-trip test of its codec, and the closed list of `needs_operator` kinds is an enumeration a test compares with the specification; every scenario loads and is served by the mock runtime, and a test per scenario asserts the representation a client receives.
