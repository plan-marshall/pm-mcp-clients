== What

A thorough visual design of the web app, made with Claude Design (the design artifacts of claude.ai, with a design system) and reviewed by the operator before any implementation:

* *Design system*: colour tokens for light and dark, typography, spacing, the components every view uses (step bar, consent, check list with checkmark and error, preselected choice, overview with drill-in, table and its list form, progress and model at work, error and fix), the harness monograms, and the icon set, chosen under a permissive licence that allows shipping it in the proprietary product (Apache-2.0, MIT, ISC, or similar; no copyleft, no attribution-only-in-UI terms the product cannot meet), with the licence recorded beside it.
* *Views*: every state of the onboarding (web side of link:../../design/web-app/onboarding.adoc[the web onboarding design]), the pairing and start pages of UC-ENT-1, the overview of running work with its two levels and two views (UC-PLN-4, link:../../design/shared/plan-overview.adoc[Plan Overview]), and first views of the plan drill-down (UC-PLN-1) and the process designer (UC-PLN-3, link:../../design/web-app/process-designer.adoc[Web App, Process Designer]); each at desktop and phone width.
* *Behaviour*: what changes when a check reports, while a model works, on a lost connection, and on a revoked device; keyboard use and accessibility (contrast, focus, screen-reader labels).
* *Technology spike*: the framework and build under the response headers of the web listener (`script-src 'self'`, Trusted Types, no inline script or style), one live-updating view and one drill-down; the result decides the toolchain of `web-app-foundation` and names the dependencies to ask the operator for.
* The accepted design: link:../../design/web-app/README.adoc[`doc/design/web-app/`] of this repository, in parts below 500 lines, with the decisions and the design tokens, linking the Claude Design artifact. It starts from what is there (its principles, the onboarding screens, the harness icons) and works out the subjects its README lists.

== Done When

The operator has accepted the design; every state of the onboarding and of the start of the web app (UC-ENT-1) has its view at both widths and in light and dark, and the first views of the plan drill-down (UC-PLN-1) and the process designer (UC-PLN-3) exist at both widths; the spike's result and the requested dependencies are recorded; the design document is merged in this repository, and the corrections of the use cases it needed are merged in `plan-marshall-documentation`.

== How It Is Run

This package is design work and is run directly in a Claude Code session, without plan-marshall and outside the epic:

. Start a Claude Code session in this repository, with a worktree of `plan-marshall-documentation` of its own for the corrections there (beside the checkouts other sessions use), and give it this file: "Work the package `web-design` of `pm-mcp-clients` (`doc/plans/web-design.adoc`)".
. The session reads the use cases, the design documents, and the specification sections of the trace above, works out the design thoroughly, and opens a pull request here with the design document in `doc/design/` and the Claude Design artifact linked from it, and one in `plan-marshall-documentation` with the corrections there.
. The operator reviews the design in the pull request here and asks for changes until it accepts it; the session merges only on the operator's word, the corrections in `plan-marshall-documentation` first.
. Once accepted, the pull request here sets the row of the package to `done` in the index in a last commit; the implementation packages that wait on it become ready.
