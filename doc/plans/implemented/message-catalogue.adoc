== What

The package implements the specification of the languages and the message catalogue listed under _Trace_. A statement of it that the implementation proves wrong is corrected in `plan-marshall-documentation` in the same plan (link:../README.adoc#how[How to Work a Package]).

* *The message format first*: how the catalogue formats its arguments is an open question (link:../../../../plan-marshall-documentation/doc/discussions/open-questions.adoc#message-format[Open Questions, Message Format]); the package proposes the format, the operator decides it, and the decision is written into the specification and the question removed, as a correction task of the documentation pull request, before the packs are written.
* The message catalogue: keys `<area>.<view>.<element>.<part>`, one pack per area and locale (`messages/<area>.<locale>.properties`, UTF-8), the lookup by key, locale and arguments.
* English complete as the base, German from the start, addressing the operator with _du_.
* The number format of tokens as link:../../design/shared/texts-and-languages.adoc#numbers[Texts and Languages, Numbers] defines it, with its keys `common.tokens.*`; a test formats every example of that section in both languages.
* The build checks: a key missing in a pack, a key not in English, a differing argument, and a glossary term translated in a German text each fail the build.
* The routes `GET /api/v1/messages` (the locales with a pack and their areas) and `GET /api/v1/messages/{locale}/{area}` added to the mock runtime of `mock-runtime`, served without a device secret, which serve the packs to the web app; the real endpoints follow with the runtime.

== Done When

The message format is decided and written into the specification; each build check has a test that makes it fail; `pm-operator` prints its texts from the catalogue in both languages; the mock runtime answers both messages routes with the packs of each language, and a test asserts it.
