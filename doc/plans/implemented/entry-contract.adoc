== What

The package implements in `pm-api` and `pm-mock-runtime` the specification sections listed under _Trace_. A statement of them that the implementation proves wrong is corrected in `plan-marshall-documentation` in the same plan (link:../README.adoc#how[How to Work a Package]).

* *The entry* (UC-ENT-1): what the terminal client reads to decide (the runtime status with the onboarding's progress, the listeners), the pairing (`POST /api/v1/web/pairings`, CLI-only), a fresh code only for the terminal client after a redemption, the LAN listener opened beside the loopback listener (`PUT /api/v1/web/listeners/lan`, CLI-only) with its certificate fingerprint and the refusal `web_listener_conflict`, the loopback `Host` without the port; the events `device.paired` (with `paired_from`) and `listener.changed`.
* *Credentials in the web app* (UC-ONB-8): the secret entered on the loopback listener only, the LAN listener refusing it with `loopback_only`.
* *Devices in both clients* (UC-ENT-2, the states `devices.list` to `devices.listener-off`): the list of paired devices with their labels (`GET /api/v1/web/devices`), rename (`PATCH`), revoke (`DELETE /api/v1/web/devices/{device_id}`), revoke all others (`DELETE /api/v1/web/devices?others`, every device when the terminal client asks), the LAN listener closed with the loopback listener left open (`DELETE /api/v1/web/listeners/lan`, accepted from a paired device), the events `device.renamed` and `device.revoked`, and the end of a revoked device's streams (`stream.closed` with `device_revoked`, `device_expired`, `listener_closed`).
* *The scenarios of the mock runtime* (`entry-<case>`): a machine not onboarded, onboarding in the terminal and in the web app, a browser of this machine paired already, an SSH session, a code redeemed and a fresh one, the LAN listener opened and refused for its port; devices renamed, revoked, all others revoked from a device and from the terminal client, the LAN listener closed from a device, a revoked device's stream ended.

== Done When

Every record and event type has a round-trip test of its codec, and every closed list (listener states, stream-end reasons) is an enumeration a test compares with the specification; every scenario loads and is served by the mock runtime, and a test per scenario asserts the representation a client receives.
