== What

The package implements in `pm-api` and `pm-mock-runtime` the specification sections listed under _Trace_. A statement of them that the implementation proves wrong is corrected in `plan-marshall-documentation` in the same plan (link:README.adoc#how[How to Work a Package]).

* *The process* (`GET /api/v1/plans/{plan_id}/process`): the tree of phases, sub-workflows and states down to the leaves, each node with its `node_id`, its kind, its state (`done`, `running`, `planned`, `waiting_for_operator`, `failed`, `not_taken`, `not_in_plan` with its prune reason), its runs and times, and for a leaf its job or its tasks, each task with a link to its activity; the path to the current position; the plan's project (`project_id`, `display_name`) and its epic, if any (`epic_id`, title), each with its link; the plan's activity and `needs_operator`; the `instance_version`; the codec.
* *The plan's tokens so far*: the unified total with its split, the count of tasks not measured (the total then a floor, where some tasks are measured), the state `not_measured` with that count where model calls happened and no task is measured (no total, no floor), none before the first model call; one step away the same by phase and by role, each with its raw components (`not_reported` or `not_applicable` per component); no budget, limit, projection, or money.
* *A worker at work*: a task's activity (`GET /api/v1/plans/{plan_id}/tasks/{queue_task_id}/activity`, an epic's tasks the same way) with the task's role, harness, model, attempt, duration, and tokens so far, its entries newest last (the model's text, each tool call with its target and whether it failed, the files changed, the questions asked), their fields untrusted plain text with secrets masked; an ended task's activity as it was; a task the server judged off track with its signal and the action taken; the activity stream (`…/activity/events`, event `activity`) a client opens only while it shows the task.
* *The events of the process*: `state.entered`, `state.left`, `subworkflow.called`, `subworkflow.returned`, `step.opened`, `step.closed`, `instance.changed`, `activity.changed`, `tokens.changed` (at most once per metrics event interval), `task.off_track`; their payloads and the codec.
* *The scenarios of the mock runtime* (`plan-view-<case>`): a plan in each phase, a loop-back, a sub-workflow nested three deep, a branch not taken, a pruned lane, a new instance version while the view is open, a plan that ends; a running task's activity growing live, an ended task's activity, a tool call that failed, a worker off track with what the server did; the tokens so far fully measured, partly measured (a floor), not measured at all after model calls (`not measured` with its coverage), none yet, and rising live.

== Done When

Every record and event type has a round-trip test of its codec, and the closed lists (node states, node kinds, activity entry kinds) are enumerations a test compares with the specification; every scenario loads and is served by the mock runtime, and a test per scenario asserts the representation a client receives.
