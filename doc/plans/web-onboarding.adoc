== What

* The onboarding route and the start and pairing pages as designed in `web-design`, rendering the states the runtime reports; one route, done steps read-only.
* Every view at desktop and phone width, light and dark, with the behaviour of the design (check lists, consent, model at work, lost connection).
* The scenarios shared with `cli-onboarding`; a scenario missing for a web case is added there.

== Trace

Requirements, specification sections, use cases, and the design documents both clients share stay in `plan-marshall-documentation` and are only referenced here; the designs of the clients are in this repository (`doc/design/`). They are the starting set; the trace matrix of `traced-implementation` is built from them before code (link:README.adoc#how[How to work a package]).

Every scenario of the onboarding and of the start of the web app (UC-WEB-1) passes as a view test; the same scenarios pass in the terminal (`cli-onboarding`); no text is written in the app's code.
