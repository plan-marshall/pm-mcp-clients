== What

* *Specification first*: the package writes the client side of Starting from the Clients and The Source Directory into `plan-marshall-documentation` as part of its own work (link:../../../plan-marshall-documentation/doc/discussions/client-specification-changes.adoc#slicing[Specification Changes for the Clients, Packages]), once the use cases are agreed, and opens that pull request beside its own.
* The records of an entry (its kind, its project, its sources with their kind, reference, state, trust, and screening verdict, the proposed title and id), of a source's failure and of a flagged source with its spans; the request that opens an entry and the one that adds each kind of source.
* The listing of files for the web app's picker, confined as the specification says.
* The representation of the entry's states for both clients (`start.choose`, `start.sources`, `start.ready`, the source sub-workflows, `recipe.choose`, `recipe.parameters`), on the scheme of `operator-interaction-contract`.
* The scenarios of the mock runtime: a plan from one description; a plan from description, documents, and an issue of another repository on Codeberg with its grant; documents copied and moved, a directory, a file tracked by git, a file refused; an issue not found and tried again; a flagged issue accepted and one removed; a lesson whose premise no longer holds; local changes; a pull request; an epic from documents; a recipe with parameters; an entry left and continued; scenario names `start-<case>`.

== Done When

The specification of the changes is merged in `plan-marshall-documentation`; every record has a round-trip test of its codec; every scenario loads and is served by the mock runtime, and a test per scenario asserts the representation a client receives.
