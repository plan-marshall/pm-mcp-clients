== What

* *Specification first*: the package writes the client side of Starting from the Clients and The Source Directory into `plan-marshall-documentation` as part of its own work (link:../../../plan-marshall-documentation/doc/discussions/client-specification-changes.adoc#slicing[Specification Changes for the Clients, Packages]), once the use cases are agreed, and opens that pull request beside its own.
* The records of an entry (its kind, its project, its sources with their kind, reference, state, trust, and screening verdict, the proposed title and id), of a source's failure and of a flagged source with its spans; the request that opens an entry and the one that adds each kind of source.
* The listing of files for the web app's picker, confined as the specification says.
* The representation of the entry's states for both clients (`start.choose`, `start.sources`, `start.ready`, the source sub-workflows, `recipe.choose`, `recipe.parameters`), on the scheme of `operator-interaction-contract`.
* The scenarios of the mock runtime: a plan from one description; a plan from description, documents, and an issue of another repository on Codeberg with its grant; documents copied and moved, a directory, a file tracked by git, a file refused; an issue not found and tried again; a flagged issue accepted and one removed; a lesson whose premise no longer holds; local changes; a pull request; an epic from documents; a recipe with parameters; an entry left and continued; a start chat (below); scenario names `start-<case>`.
* *The start chat* (the sub-workflow `chat` of `pm-mcp-core`, represented as in `control-contract`): _Chat_ as a link of `start.sources` and `start-epic.sources`, available once a source is stored and every source from outside the machine is screened, disabled with its reason while the role does not qualify, absent for a recipe; the entry as its scope and its routed role (`refine` for a plan, `decompose` for an epic); a description rewritten or added, read back and stored through `start.store-description`; the transcript kept with the entry and moved with its source directory at `start.create`, deleted when the entry is abandoned; a chat still open at create or abandon ended first, its transcript complete. Scenarios: a plan's entry with a question only, an addition to the description accepted, a rewrite rejected, an epic's entry, a description-only entry with Chat available at once, Chat disabled while an issue is not yet screened, a create and an abandon each while a chat is still open (the chat ended and its transcript complete before the source directory moves or is deleted).
* *The follow-up plan of a chat about ended work* (`control-contract`): the entry the accepted proposal opens, with its description stored and the ended plan or epic named in it, at `start.sources`; scenario `start-follow-up`, with one case from an ended plan and one from an ended epic.
