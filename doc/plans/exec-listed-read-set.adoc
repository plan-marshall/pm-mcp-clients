== What

* A mode of `pm-exec` in which the read set is only what the runtime lists: no read rule on `/`, no enumeration
  around denied paths, the `--read` paths and the write set the only readable places. A worker launch uses it; every
  other job keeps the enumerated read set. Combining the listed mode with `--deny-read` is a usage error (exit `64`),
  because in that mode nothing is readable that is not granted.
* The launch report keeps its fields; the mode is visible to the runtime from the argument vector it passed.
* The member `headless.readable_paths` in every shipped profile document of `pm-api`, empty and _(provisional)_ until
  the `paths` stage of the profile verification has measured each harness in confinement.
* The macOS sandbox profile, where `pm-exec` applies it, grants a worker the same listed read set.

== Done When

`PmExecIT` under Landlock: in the listed mode a job reads its `--read` paths and its write set and fails to read a
file directly in the home directory, `<PM_MCP_BASE>`, and a sibling of a listed path; the same job without the mode
still reads the home directory (matched control); `--deny-read` with the listed mode exits `64`. Every shipped profile
document validates with `headless.readable_paths`.
