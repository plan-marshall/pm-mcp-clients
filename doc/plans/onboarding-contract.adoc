== What

* *Specification first*: the package writes its part of the specification into `plan-marshall-documentation` as part of its own work (link:../../../plan-marshall-documentation/doc/discussions/client-specification-changes.adoc#slicing[Specification Changes for the Clients, Packages]), from the use case once it is agreed, and opens that pull request beside its own; the proposal's rows it writes are removed from the proposal.
* *Contract*: the onboarding's stores and steps: consents (the closed list of kinds with `check_credential_store` and `verify_providers`, `consents.json`), languages as far as `message-catalogue` leaves them, the harnesses from one scan with their default (`harness.none` also when every chosen harness fails), the login probe and unknown harness, the model catalogue, the steward (on the default harness, outside the catalogue), the default and machine role assignment, the credential store, the providers and their verification, the plan axes with the variants `landing.pull-request`, `landing.main`, `landing.files`, the plan overrides, the harness icons; the machine settings (UC-ONB-10): `settings.choose`, withdrawing a remembered consent, `sources.documents_mode`, a credential rotated or replaced with its verification; the onboarding scenarios of the mock runtime (`onboarding-<case>`).
* *Automatic onboarding*: `auto.consent`, the closed list of reasons and the item schema of `auto.result`.

== Done When

The specification of the use case's changes is merged in `plan-marshall-documentation`; every record and event type has a round-trip test of its codec, and every closed list is an enumeration a test compares with the specification; every scenario loads and is served by the mock runtime, and a test per scenario asserts the representation a client receives.
