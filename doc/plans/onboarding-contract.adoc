== What

* *Specification first*: the package writes its part of the specification into `plan-marshall-documentation` as part of its own work (link:../../../plan-marshall-documentation/doc/discussions/client-specification-changes.adoc#slicing[Specification Changes for the Clients, Packages]), from the use case once it is agreed, and opens that pull request beside its own; the proposal's rows it writes are removed from the proposal.
* *Contract*: the onboarding's stores and steps: consents (the closed list of kinds with `check_credential_store` and `verify_providers`, `consents.json`), languages as far as `message-catalogue` leaves them, the harnesses from one scan with their default (`harness.none` also when every chosen harness fails), the login probe and unknown harness, the model catalogue, the steward (on the default harness, outside the catalogue), the default and machine role assignment, the credential store, the providers and their verification, the plan axes with the variants `landing.pull-request`, `landing.main`, `landing.files`, the plan overrides, the harness icons; the machine settings (UC-ONB-10): `settings.choose`, withdrawing a remembered consent, `sources.documents_mode`, a credential rotated or replaced with its verification; the revision every settings change carries and the error code `conflict` (`409`) of a change against an older revision, returning the current value (one representation, used again by `project-contract` and `control-contract`; link:../design/shared/work-actions.adoc#conflict[Changed in Two Clients at Once]), with the scenario `onboarding-settings-conflict` (the documents mode changed in two clients, the second refused and applied again); the onboarding scenarios of the mock runtime (`onboarding-<case>`).
* *Tokens, not money* (link:../../../plan-marshall-documentation/doc/use-cases/03-plans.adoc#change-token-usage[Tokens, Not Money], the core's `token-usage`): the consent field `tokens` in place of a cost, an estimate in tokens with the number of earlier runs, or not known yet, never money (the kind `model_cost` keeps its name); each harness of the scan, the enrolment, and the machine settings with what this harness and version reports of its usage (`complete`, `partial` with the figures missing, `not_reported`; per figure `reported`, `not_applicable`, `not_reported`), from its profile and its verification; the verification's stage `usage` with its result; the scenarios a harness complete, partial, and not reporting, and the stage `usage` failing on a figure the draft names (`onboarding-harness-tokens-<case>`).
* *Automatic onboarding*: `auto.consent`, the closed list of reasons and the item schema of `auto.result`.

== Done When

The specification of the use case's changes is merged in `plan-marshall-documentation`; every record and event type has a round-trip test of its codec, and every closed list is an enumeration a test compares with the specification; every scenario loads and is served by the mock runtime, and a test per scenario asserts the representation a client receives.
