== What

The package implements in `pm-api` and `pm-mock-runtime` the specification sections listed under _Trace_, which every other contract package builds on. A statement of them that the implementation proves wrong is corrected in `plan-marshall-documentation` in the same plan (link:README.adoc#how[How to Work a Package]).

* *A state for a client*: the operator representation of a state (`scope`, `state` with its `state_id`, `node_id`, kind, and `level`, `progress`, `title` and `texts`, `facts`, the proposal, items with what is not offered and why, links) and of every other resource with its relations; the operator link `{id, rel, method, href, params, preselected, confirm}` and how a client follows one at its `href`; a link of a state left meanwhile refused `act_not_available`, an act against an older revision refused `conflict` with the current revision.
* *The event catalogue*: the envelope (`event`, `id`, `data` with `event`, `at`, `scope`), the closed catalogue of event names with one payload schema each, `Last-Event-ID` and `reset`, `stream.closed` with its reasons; the streams of the runtime, a plan, an epic, a project's workspace scope, the machine, an entry, the reports, and a task's activity.
* *Texts of the runtime*: which fields are message keys with arguments and which are verbatim external or model text.
* *Error codes*: the closed list of the local API with their HTTP status, as one enumeration.
* *Configuration and levels*: every value with its origin (`default`, `derived`, `machine`, `team`, `project`, `plan`) and what it overrides; `set` and `unset` per key and level, each change carrying its revision; a later run of an aspect for a project or a plan; the refusals `aspect_owned` and `onboarding_incomplete`.
* *Client inputs and files*: the client's locale as `Accept-Language`, the login environment the terminal client captures, the SSH session as the client's own observation; the client-owned files outside `<PM_MCP_BASE>` among the direct file reads; `console.notify` and `console.full_screen` in `machine-config.json`.
* *The mock runtime*: scenario links keyed by the operator link's `id`, events named from the catalogue, a moved state answered as the runtime answers it.

== Done When

Every record, link, and event type has a round-trip test of its codec, and every closed list (event names, error codes, origins, stream-end reasons) is an enumeration a test compares with the specification; the mock runtime serves a scenario with operator links, check events, and a moved state, and a test asserts each.
