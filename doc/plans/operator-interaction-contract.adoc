== What

* *Specification first*: the package writes its part of the specification into `plan-marshall-documentation` as part of its own work (link:../../../plan-marshall-documentation/doc/discussions/client-specification-changes.adoc#slicing[Specification Changes for the Clients, Packages]), and opens that pull request beside its own; the proposal's rows it writes are removed from the proposal.
* *A state for a client*: the representation of a state the operator acts on (its id, kind, step, level, facts, proposal, items with what is not offered and why, links), the scheme of the operator's links over the local API and how a client follows one, and the refusal of a link to a state that moved on (`state_moved`).
* *The event catalogue*: the envelope, closed type names, payload schemas, `Last-Event-ID` and `reset` per stream; the streams of a plan, an epic, the workspace, and the machine.
* *Texts of the runtime*: which fields are message keys with arguments and which are verbatim external or model text.
* *Client inputs and files*: the client's locale, login `PATH`, and SSH session as request fields; the client-owned files outside `<PM_MCP_BASE>` as an exception to the closed list of direct file reads; `console.notify` and `console.full_screen` in `machine-config.json`.

== Done When

The specification of these four parts is merged in `plan-marshall-documentation`; every record, link, and event type has a round-trip test of its codec and every closed list is an enumeration a test compares with the specification; the mock runtime serves a scenario with operator links, check events, and a moved state, and a test asserts each.
