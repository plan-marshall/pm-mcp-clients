== What

The runtime lays out a phase's workflow and a plan's change map as positioned data; a model may write a diagram as a Mermaid block where the operator chose that format. This package shows both in the web app without weakening its security headers.

* *Design first*: the package adds to link:../design/shared/plan-view.adoc[Plan View] how a workflow and the change map are shown as a diagram beside the tree, and how a Mermaid block in model text is shown, and has the operator accept it before building it.
* *Contract*: the two layout endpoints and their answer (`too_large`, an `indeterminate` change map) in `pm-api`, with scenario files of `pm-mock-runtime` for a unit, a change map, and an oversized graph.
* *Drawing a layout*: Svelte SVG elements at the given positions, styled by classes and the web app's theme tokens, the states joined from the process answer by `node_id`, the plan's position marked; labels in the diagram font (Arial, Liberation Sans) the server measured with. No received markup is inserted.
* *Mermaid in model text*: `pele` (MIT, no runtime dependency; its licence notices kept in the bundle) renders the block with links, images, and icons off and its source bound; the SVG string becomes a Blob shown through an object URL, with the colours of both schemes written into it; a refused block shows its source and the error as text.
* *The setting*: `diagrams.format` (`text`, `mermaid`) for the machine and for a project, in both clients, texts from the message catalogue.
