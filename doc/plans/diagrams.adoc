== Tasks

. Design how a workflow and the change map are shown as a diagram beside the tree, and how a Mermaid block of model text is shown, in link:../design/shared/plan-view.adoc[Plan View]; the operator accepts the design before the build.
. The two layout endpoints and their answers in `pm-api`, with scenario files of `pm-mock-runtime` for a unit, a change map, and an oversized graph.
  Anchor: link:../../../plan-marshall-documentation/doc/specification/runtime-model/01-processes-and-transport.adoc#process-layout[Runtime & Interaction Model § Layout]; link:../../../pm-mcp-core/doc/specification/workflow-dsl/07-loop-back-diagrams-verification.adoc#diagram-layout[Workflow DSL § Positioned Layout].
  Proof: contract tests against the scenarios.
. Drawing a layout in the web app.
  Anchor: link:../../../plan-marshall-documentation/doc/specification/cli-and-security/03-web-server.adoc#web-diagrams[CLI, Coordination & Security § Diagrams].
  Proof: the web app's tests draw the fixture layouts with every label within its box (PM-WATCH-DSL-38).
. A Mermaid block of model text as an image.
  Anchor: link:../../../plan-marshall-documentation/doc/specification/cli-and-security/03-web-server.adoc#web-diagrams[CLI, Coordination & Security § Diagrams].
  Proof: the web app's tests show a block as an image and a refused block as its source, with the runtime's security headers unchanged.
. The setting `diagrams.format` for the machine and a project, in both clients.
  Anchor: link:../../../pm-mcp-core/doc/specification/store-schemas/08-project-configuration-local.adoc#project-levels[Store Schemas § Project Values over Machine Values].
  Proof: both clients set and show the setting in their tests.
