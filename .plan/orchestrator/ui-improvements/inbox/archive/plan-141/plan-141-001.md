  `intent-record-v1.schema.json` carries `choices[].adr {adr_id, relation}`, `choices[].evidence`, `non_goals[]` as
  `{id, text}`, decider `role`; the builder check records `not_run` with its reason. The gap is `pm-api`
  (`PlanIntentResource.Decision`, `IntentDecider.MODEL("model")`, `BuilderCheckResource`). Vote support: absent in both.
- CONFIRMED: `syncUrl` (`runtime.ts:906-917`) writes `{ path }` into `history.state` for every entry; nothing reads it.
- Derived from Q1 (in the PR body): with a task as a level, the default selection on load is the node holding the
  running task, not the task; a task opens on selection or under `follow=on`.
